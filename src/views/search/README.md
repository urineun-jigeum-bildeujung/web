## 짚어둘 것

**이 화면은 `(constrained)` 그룹 밖이라 폭을 스스로 진다(#573).** 최상위 래퍼가 `mx-auto flex min-h-dvh w-full max-w-300 flex-col`이고 1200은 브레이크포인트가 아니라 최대 폭이다. **상품 격자가 없어 열 수 문제에 걸리지 않는다** — 768 시안(2656-32932 빈 화면, 2675-33685 찬 화면)도 제목 줄이 `fill`이라 화면 폭을 그대로 쓴다. 거터는 래퍼가 아니라 섹션이 `px-5`로 진다.

**768 찬 화면 시안의 칩 줄만 폭이 `fixed 393px`이다(2675:33697).** 바로 위 제목 줄과 393 시안의 같은 줄(2396:80498)이 모두 `fill`이라 768로 복사할 때 폭을 되돌리지 않은 자국으로 보고, 넓은 폭에서도 흐르게 뒀다. PD가 2026-09-30에 반응형 시안 추가 작업이 없다고 확정해 재확인을 기다리지 않았다.

**최근 검색어 섹션 수치는 393·768 시안이 같다.** 거터 20px, 제목 줄↔칩 줄 8px, 칩 줄 가로 8px·세로 12px이다(2396-80494·80498). #573에서 `px-4`·`gap-3`·`gap-2`였던 것을 이 값으로 맞췄다.

**"전체삭제"는 보이는 크기를 시안대로 두고 누르는 자리만 `after:`로 넓힌다.** `min-h-11`로 실제 상자를 44px로 키우던 동안 이 버튼이 제목 줄 높이를 44px로 밀어 올려, `items-center`가 24px 제목을 그 안에 가운데 두면서 시안이 8px인 제목 글자↔칩 줄 간격이 18px이 됐다. 세로만 11px씩 넓히는 것은 `product-detail-view`의 같은 텍스트 버튼과 같은 기법이고, 정렬 드롭다운처럼 가로도 11px씩 넓히면 옆 요소와 탭 영역이 겹친다(#265). 실측 탭 영역은 58×44다.

**이 화면만 머리말에 `PageHeader`를 쓰지 않는다.** 제목 자리를 입력창이 차지하기 때문이다. `PageHeader`는 가운데 제목을 전제로 3열 그리드를 잡아서 맞지 않는다. 대신 뒤로가기는 모든 헤더와 같은 `HeaderBackButton`이고, 높이 48·좌우 20에 입력창이 뒤로가기 누르는 자리 바로 옆에서 시작한다(시안 1117-9724, #513). 검색 결과 화면의 머리말도 같다.

**들어오면 입력창에 바로 초점을 준다.** 검색하러 온 화면인데 한 번 더 눌러 입력을 시작하게 만들지 않는다.

**최근 검색어 칩은 버튼 두 개를 나란히 둔다.** 칩 안에 삭제 버튼을 겹쳐 넣으면 눌리지 않고, 탭 영역이 겹치면 지우려다 검색된다. `shared/ui/filter-chips`는 하나를 고르는 칩이라 여기 쓰지 않는다 — 기준은 [component-convention](../../../docs/conventions/component-convention.md)의 "공용으로 올리는 기준"을 본다.

**최근 검색어는 `useSyncExternalStore`로 잇는다.** 저장소는 React 밖의 것이라, 효과 안에서 `setState`로 되읽으면 React Compiler가 연쇄 렌더로 잡는다. 서버 스냅숏을 따로 주어 프리렌더된 HTML과 첫 그림이 어긋나지 않게 한다.

**서버 스냅숏은 `null`(아직 모름)이고, 저장된 것이 없으면 빈 목록이다.** 전에는 둘 다 시안에 그려진 예시 다섯 개("고양이 화장실 모래" 등)를 돌려줘, 검색한 적 없는 사람에게도 그 말들이 최근 검색어로 떴다. 모르는 동안에는 칩도 빈 상태도 그리지 않는다 — 빈 상태를 먼저 그리면 저장된 검색어가 있는 사람에게 "내역이 없어요"가 잠깐 떴다 사라진다 (#479).

**IA가 최근 검색어를 최대 5개로 못 박고 있다.** 상한이 없으면 화면 절반이 최근 검색어가 된다.

**추천어 강조는 색만으로 하지 않는다.** `<strong>`으로 굵기를 함께 줘서 색을 구분하기 어려운 사람도 어느 부분이 겹쳤는지 안다.

**비교 자리를 채우러 왔으면(`slot` 있음) 하단이 `BottomNav` 대신 "선택 완료" 액션 바다.** 이 화면 자체는 아직 결과가 없어 늘 비활성이고, 실제로 눌리는 곳은 [search-result](../search-result/README.md)다. Figma(#245, 1117-9724·1117-6366)가 검색어 입력 전·입력 중 화면에도 이 바를 그린다.

**"카테고리로 둘러보기" 섹션이 없다.** 검색 흐름 시안 세 장(2396-80473 · 2396-80487 · 2396-80432) 어디에도 이 섹션이 없고, 2026-09-29 디자인 QA 2차 댓글에서 카테고리를 빼는 것으로 확정됐다 (#499). 비교 자리를 채우러 온 경우(`slot` 있음)는 1117-9724를 근거로 그 전부터 그리지 않고 있었다. 안내 문구("비교할 상품을 검색해 주세요")도 시안에 없어 그때 함께 뺐다 — 예전 와이어프레임 문구를 그대로 남겨 둔 것이었다.

**최근 검색어 없음 상태는 공용 `EmptyState`를 쓰지 않는다.** 그 컴포넌트는 72px 아이콘·18px 제목 시안(메인 타임딜 빈 상태) 기준인데, 이 화면(2396-80473)은 40px 아이콘에 14px 두 줄로 훨씬 작다. 억지로 맞추면 다른 화면(타임딜 등)의 확정된 크기가 깨진다.

## 아직 정하지 않은 것

**최근 검색어 칩이 시안보다 6px 넓어, 393에서 시안의 2줄이 3줄이 된다.** 칩 폭이 글자폭+58px인데 시안(2396-80499 등)은 글자폭+52px이다 — 글자↔아이콘 간격이 시안 4px인데 `pr-1`+`pl-1`로 8px이고(+4px), CSS `border` 1px 양쪽이 폭에 더해진다(Figma stroke는 프레임 폭에 안 들어간다, +2px). 시안 폭으로 다시 나눠 보면 정확히 2줄이고 시안 프레임 높이 92px(=40+12+40)과 맞는다.

**그런데 시안대로 맞춰도 여유가 1.5px뿐이다.** 간격만 4px로 줄이면 글자폭+54px이 되어 첫 줄이 354.46px로 353px을 1.46px 넘겨 여전히 3줄이다. 테두리 2px까지 없애야 2줄이 되는데, 그 폭을 4px 스케일로 맞추려면 좌우 패딩이 11px이어야 한다. 글꼴 렌더링 차이로 뒤집힐 수 있는 간격이라 임의로 맞추지 않고 남긴다 — `RecentKeywordChip`의 헤더 주석이 적은 대로 이 칩은 아직 와이어프레임 기준이다. 줄 수를 시안과 맞추려면 PD와 칩 여백을 확정해야 한다.

**추천어를 무엇으로 채울지 정해지지 않았다.** 지금은 목업 목록에서 입력한 글자가 들어간 것을 고른다. 기획 확정 후 서버에서 받는다.

**최근 검색어를 서버에 둘지 기기에 둘지 정해지지 않았다.** 지금은 기기(`localStorage`)에 남긴다. API 계약이 정해지면 `model/recent-keywords.ts` 하나만 갈아끼우면 되도록 읽고 쓰는 자리를 모아 뒀다.
