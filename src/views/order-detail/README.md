| 파일 | 설명 |
| --- | --- |
| `ui/order-detail-view.tsx` | 주문정보·결제상세·배송지 정보 세 카드를 조립한다 |
| `ui/order-detail-view.test.tsx` | 카드 구성, 주문별 내용, 반품·교환 접수 조건을 본다 |

## 라우트

`/mypage/orders/[orderId]` — `src/app/mypage/orders/[orderId]/page.tsx`. 주문·배송 화면의 "자세히 보기"가 여기로 온다.

## 반품·교환은 배송이 끝나야 접수한다

`mypa_161_배송완료`에만 버튼이 그려져 있다. 배송 전에는 주문 취소가 맞는 길이라 그 상태에서는 자리를 만들지 않는다.

**누르면 바로 접수되지 않고 확인창이 한 번 막는다.** 접수하면 기사가 상품을 가지러 오고 그 뒤에야 환불이나 교환이 진행되므로, 무슨 일이 일어나는지 알린 뒤 확인받아야 한다. 되돌릴 수 없는 행동이라 `Dialog`가 아니라 `AlertDialog`를 쓴다.

**반품과 교환은 수거 뒤에 오는 것이 다르다.** 반품은 "바로 환불해 드릴게요", 교환은 "새 상품을 보내드릴게요"다. 시안 문구 그대로다.

버튼과 확인창만 클라이언트 컴포넌트(`claim-actions.tsx`)로 갈랐다. 나머지 화면은 서버 컴포넌트로 남는다.

## 반품·교환 링크를 걷었다

전에는 화면 아래 링크 줄에 반품·교환이 `?type=return|exchange`로 있었다. 시안이 나와 확인창으로 옮겼고 링크에서는 뺐다(#139). **`/mypage/orders/[orderId]/claim` 라우트는 남는다** — 주문 취소가 아직 그 화면을 쓴다.

## DetailCard는 shared로 옮겼다

주문 완료(`paym_002`)에 같은 모양이 나와 `shared/ui/detail-card`로 올렸다. 처음에는 이 화면만 써서 여기 두었던 것이다.

## 아직 없는 것

값이 모두 목 데이터다. 주문 ID로 조회하는 훅은 API 계약이 정해진 뒤에 붙인다.

반품·교환 접수 API도 없다. 확인창의 접수 버튼은 토스트로 끝난다.
