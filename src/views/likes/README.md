# views/likes

찜한 상품·최근에 본 상품·자주 산 상품을 탭으로 나눠 본다. 찜 탭은 UI 시안(`#274`, 1117-4972, 빈 상태 2022-158710)에 대응한다. "최근에 봤어요"·"자주 샀어요"는 PD 확인 결과 이번 MVP 범위 밖이라 탭은 남겨두고 눌러도 반응하지 않는다(#274 QA 답변).

| 파일 | 설명 |
| --- | --- |
| `ui/likes-view.tsx` | 좋아요 세 탭 (찜 탭만 확정 시안, 나머지 두 탭은 비활성) |
| `ui/likes-view.test.tsx` | 탭마다 무엇이 붙는지, 카테고리로 거르기가 목록을 줄이는지 본다 |
| `index.ts` | 공개 API |

## 라우트

```text
/likes?tab=liked&category=all|food|snack|supplement
```

하단 이동 줄의 "좋아요"가 여기로 온다. 찜 탭의 카테고리를 주소에 남겨 상품 상세에 갔다 돌아와도 보던 자리가 유지되게 한다. `category`는 `/recommendations`와 같은 값 체계다.

`tab`은 `liked` 하나만 받는다. 최근에 봤어요·자주 샀어요는 탭 UI만 있고 `?tab=recent`처럼 주소로 직접 넣어도 `liked`로 떨어진다 — 탭 클릭만 막으면 주소로는 비활성 탭에 들어가 지우기 동작을 쓸 수 있었다(CodeRabbit 지적, PR #285).

## 헤더는 뒤로가기 있는 PageHeader다

`/likes`가 바텀내비 탭 루트라 home-view와 같은 로고형일 거라 짐작해 한 번 걷어냈었는데, 시안(header, 1585:18342)을 다시 보니 뒤로가기 화살표+검색·알림·장바구니고 제목이 없다. `PageHeader`(기본값 `leading="back"`, `title` 없음)로 되돌린다.

## 탭마다 카드에 붙는 것이 다르다

| 탭 | 이미지 위 | 이미지 안 | 카드 아래 |
| --- | --- | --- | --- |
| 찜했어요 | 흰 원판+채워진 하트(누르면 바로 풂), 사진 오른쪽 위(4px) | — | — |
| 최근에 봤어요 | 지우기 | — | — |
| 자주 샀어요 | 지우기 | 구매 횟수·마지막 구매 | 장바구니·구매하기 |

`shared/ui/product-grid-card`가 이 자리들을 슬롯으로 받는다. 화면 수만큼 boolean을 늘리는 대신 무엇을 놓을지 넘긴다. 찜 탭만 `imageActionClassName`으로 자리를 사진 오른쪽 위 4px로 옮긴다(공용 기본값은 12px) — 나머지 두 탭은 확정 시안이 없어 공용 기본 위치를 그대로 둔다.

## 찜 탭은 카테고리로 거른다

시안(1117-4972)의 칩은 "전체"·"사료"·"간식"·"영양제"다(PD가 알림 상태에서 카테고리로 바꿨다, #274 QA 답변). `shared/ui/filter-chips`를 그대로 재사용한다(36px 알약·고른 것만 `bg-primary`가 시안값과 정확히 일치).

## 아직 없는 것

- 목록이 목업이다. 찜·삭제가 서버에 남지 않아 새로고침하면 되돌아간다
- "장바구니"와 "구매하기"가 그 화면으로 가기만 하고 고른 상품을 함께 넘기지 못한다. 장바구니의 "결제하기"와 같은 수준이며, 화면 간 전달은 라우터 구조가 정해진 뒤에 붙인다

## 최근에 봤어요·자주 샀어요는 탭도 주소도 막혀 있다

PD 확인 결과 두 탭 다 이번 MVP 범위 밖이다(#274 QA 답변). 탭 자체는 시안대로 남겨두고 `TabsTrigger`에 `disabled`만 준다. `tab` 쿼리도 `liked` 하나만 받게 좁혀서, `?tab=recent`처럼 주소로 직접 들어와도 우회할 수 없다 — 목록·지우기 로직은 코드에 남아 있지만 어느 경로로도 도달할 수 없는 상태다.

찜한 상품 중 고른 카테고리에만 상품이 없을 때는 "이 카테고리엔 담아둔 상품이 없어요"로, 찜한 상품 자체가 없을 때는 "아직 담아둔 상품이 없어요"로 문구를 나눈다 — 둘 다 확정 시안은 없다.

## 찜 탭의 하트는 확인 없이 바로 풀린다

찜 목록엔 한 번에 여러 개를 취소하는 기능이 없어 하나씩 눌러야 하는데, 그때마다 확인 모달·토스트가 뜨면 오히려 방해된다는 PD 판단이다(#274 QA 답변). 하트를 누르면 확인창 없이 바로 목록에서 빠진다.

최근에 봤어요·자주 샀어요 탭의 지우기(X)는 여전히 확인창(`AlertDialog`)을 거친다 — 이 확인창 자체는 확정 시안이 없어 문구·버튼 구성은 기존 와이어프레임 그대로다.
