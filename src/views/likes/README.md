# views/likes

찜한 상품·최근에 본 상품·자주 산 상품을 탭으로 나눠 본다. 찜 탭은 UI 시안(`#274`, 1117-4972, 빈 상태 2022-158710)에 대응하고, "최근에 봤어요"·"자주 샀어요"는 이번 시안에 없어 와이어프레임 스타일 그대로 남아 있다.

| 파일 | 설명 |
| --- | --- |
| `ui/likes-view.tsx` | 좋아요 세 탭 (찜 탭만 확정 시안) |
| `ui/likes-view.test.tsx` | 탭마다 무엇이 붙는지, 알림 상태로 거르기가 목록을 줄이는지 본다 |
| `index.ts` | 공개 API |

## 라우트

```text
/likes?tab=liked|recent|often&notice=all|new|seen
```

하단 이동 줄의 "좋아요"가 여기로 온다. 탭과 찜 탭의 알림 상태를 주소에 남겨 상품 상세에 갔다 돌아와도 보던 자리가 유지되게 한다.

## 헤더가 로고형이다

`/likes`는 바텀내비 4개 경로 중 하나(탭 루트)라 `PageHeader`(뒤로가기+제목) 대신 home-view와 같은 로고형 헤더(로고+검색+알림+장바구니)를 쓴다. 이전엔 `PageHeader leading="none"`을 썼는데, 시안(1117-4972)을 다시 보니 탭 루트 화면 규칙과 어긋나 있었다.

## 탭마다 카드에 붙는 것이 다르다

| 탭 | 이미지 위 | 이미지 안 | 카드 아래 |
| --- | --- | --- | --- |
| 찜했어요 | 흰 원판+채워진 하트(누르면 품), 사진 오른쪽 아래 | — | — |
| 최근에 봤어요 | 지우기 | — | — |
| 자주 샀어요 | 지우기 | 구매 횟수·마지막 구매 | 장바구니·구매하기 |

`shared/ui/product-grid-card`가 이 자리들을 슬롯으로 받는다. 화면 수만큼 boolean을 늘리는 대신 무엇을 놓을지 넘긴다. 찜 탭만 `imageActionClassName`으로 자리를 사진 오른쪽 아래로 옮긴다 — 나머지 두 탭은 확정 시안이 없어 공용 기본 위치(오른쪽 위)를 그대로 둔다.

## 찜 탭은 알림 상태로 거른다

시안(1117-4972)의 칩은 상품 종류가 아니라 "전체"·"새 알림"·"확인한 알림"이다. `shared/ui/filter-chips`를 그대로 재사용한다(36px 알약·고른 것만 `bg-primary`가 시안값과 정확히 일치).

## 아직 없는 것

- 목록이 목업이다. 찜·삭제가 서버에 남지 않아 새로고침하면 되돌아간다
- "장바구니"와 "구매하기"가 그 화면으로 가기만 하고 고른 상품을 함께 넘기지 못한다. 장바구니의 "결제하기"와 같은 수준이며, 화면 간 전달은 라우터 구조가 정해진 뒤에 붙인다
- "새 알림"/"확인한 알림"이 정확히 무엇에 대한 알림인지(재입고·가격 인하 등) Figma에 문구가 없다. 시안 라벨만 옮겼고, 실제 의미와 상품을 보면 자동으로 "확인함"이 되는지는 PD팀 확인이 필요하다(개인 QA 기록)
- "최근에 봤어요"·"자주 샀어요"가 MVP 범위 안인지 확정되지 않았다 — 이슈 #274엔 "시안이 나오면 별도로 처리한다"고만 적혀 있어, 시안 대기 중인지 애초에 범위 밖인지 PD팀 확인이 필요하다(개인 QA 기록)

## 빼기는 세 탭 모두 확인을 거친다

찜 탭의 하트도 누르면 목록에서 빠진다. 하트만 비우고 목록에 남기면 푼 것이 아니다. 되돌릴 수 없는 동작이라 다른 탭과 같이 확인창으로 막고, 탭마다 무엇을 뺀다고 부르는지만 다르게 적는다.

**이 확인창(`AlertDialog`) 자체는 이번에 받은 두 시안 노드 어디에도 없어 Figma와 대조하지 못했다.** 문구·버튼 구성은 기존 와이어프레임 그대로다. 확정 시안이 있는지, 있다면 지금과 같은지 프디팀 확인이 필요하다(개인 QA 기록).
