# views/likes

찜한 상품·최근에 본 상품·자주 산 상품을 탭으로 나눠 본다. 와이어프레임 `like_001` 계열 4장에 대응한다.

| 파일 | 설명 |
| --- | --- |
| `ui/likes-view.tsx` | 좋아요 세 탭 (`like_001_찜`, `like_001_최근`) |
| `ui/likes-view.test.tsx` | 탭마다 무엇이 붙는지, 거르기가 목록을 줄이는지 본다 |
| `index.ts` | 공개 API |

## 라우트

```text
/likes?tab=liked|recent|often&category=<종류>
```

하단 이동 줄의 "좋아요"가 여기로 온다. 탭과 종류를 주소에 남겨 상품 상세에 갔다 돌아와도 보던 자리가 유지되게 한다.

## 탭마다 카드에 붙는 것이 다르다

| 탭 | 이미지 위 | 이미지 안 | 카드 아래 |
| --- | --- | --- | --- |
| 찜했어요 | 하트(누르면 품) | — | — |
| 최근에 봤어요 | 지우기 | — | — |
| 자주 샀어요 | 지우기 | 구매 횟수·마지막 구매 | 장바구니·구매하기 |

`shared/ui/product-grid-card`가 이 자리들을 슬롯으로 받는다. 화면 수만큼 boolean을 늘리는 대신 무엇을 놓을지 넘긴다.

종류로 거르는 칩은 찜 탭에만 있다. 시안이 그렇다.

## 아직 없는 것

- 목록이 목업이다. 찜·삭제가 서버에 남지 않아 새로고침하면 되돌아간다
- "장바구니"와 "구매하기"가 그 화면으로 가기만 하고 고른 상품을 함께 넘기지 못한다. 장바구니의 "결제하기"와 같은 수준이며, 화면 간 전달은 라우터 구조가 정해진 뒤에 붙인다

## 빼기는 세 탭 모두 확인을 거친다

찜 탭의 하트도 누르면 목록에서 빠진다. 하트만 비우고 목록에 남기면 푼 것이 아니다. 되돌릴 수 없는 동작이라 다른 탭과 같이 확인창으로 막고, 탭마다 무엇을 뺀다고 부르는지만 다르게 적는다.
