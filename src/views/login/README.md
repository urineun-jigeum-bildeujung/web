# login

로그인. 아이디·비밀번호로 들어오거나 소셜로 들어온다.

- **라우트**: `/login` — `src/app/login/page.tsx`
- **조립**: `shared/ui`의 `form-field` · `checkbox-row` · `button`
- **상태**: 입력값과 자동로그인 여부 모두 화면 안 상태. 소셜은 서버 상태 없이 주소 이동뿐
- **참고**: UI 시안 기준(sign_001 로그인, `1117-4927`)

| 파일 | 설명 |
| --- | --- |
| `ui/login-view.tsx` | 화면 조립 |
| `ui/login-view.test.tsx` | 소셜 링크가 가리키는 주소, 제공자 두 갈래 |
| `config/oauth.ts` | 소셜 로그인 시작 주소와 제공자 목록 |
| `index.ts` | 공개 API |

## 짚어둘 것

**소셜은 카카오·구글 둘이다.** 시안에는 넷(카카오·네이버·애플·구글)이 원형 아이콘으로 그려져 있으나, 인증 정책이 카카오·구글로 확정돼 그에 맞췄다. 시안의 아이디·비밀번호 폼은 정책상 관리자 전용이라 일반 회원 화면에 둘지 PD·PM 확인이 남아 있다(#184).

**로고는 react-icons다.** 디자인 시스템 아이콘 세트 밖이라 브랜드 글리프(`RiKakaoTalkFill`·`FcGoogle`)를 쓴다. 배경이 필요한 카카오만 `--kakao` 토큰을 `globals.css`에 뒀다. 카카오가 규정한 색이라 우리 팔레트와 무관하게 고정이다.

**"골라주개냥"은 검정이다.** 시안 텍스트가 검정이고 그 뒤의 분홍 사각형은 메모용 표시로 봤다. 브랜드색 강조가 의도라면 바꾼다(#184).

**아이디·비밀번호 찾기는 링크를 걸지 않았다.** 갈 화면이 시안에 아직 없다. 링크를 걸면 404가 되고 버튼으로 두면 눌러도 아무 일이 없어 고장으로 읽힌다 — `ListRowStatic`과 같은 판단이다. 화면이 생기면 링크로 바꾼다.

**소셜 버튼은 링크다.** 인증 제공자 화면으로 리다이렉트되는 흐름이라 fetch로는 따라갈 수 없다. 브라우저를 통째로 보내는 이동이므로 `button`이 아니라 `a`를 쓴다 — 새 탭으로 열기·주소 복사 같은 기본 동작이 따라오고 스크린 리더도 이동으로 읽는다.

**시작 주소만 `/api/v1`이 아니다.** 게이트웨이가 일반 API(`/api/v1/**`)와 별개로 `/api/auth/oauth2/authorization/**`를 Spring Security OAuth2 클라이언트로 보낸다. `NEXT_PUBLIC_API_BASE_URL`에서 파생할 수 없어 `NEXT_PUBLIC_OAUTH_BASE_URL`을 따로 받는다.

## 아직 정하지 않은 것

**자사 아이디·비밀번호 로그인은 붙일 API가 없다.** 백엔드에 있는 것은 관리자용 `/auths/admin/*`뿐이고 그마저 미구현이다. 폼을 일반 회원 화면에서 뺄지는 PD·PM 확인이 남아 있다(#184). 그때까지 시안대로 둔다.
