# views/home

메인 화면. 와이어프레임 `메인` 계열 여섯 장에 대응한다.

| 파일 | 설명 |
| --- | --- |
| `ui/home-view.tsx` | 메인 (`메인`, `메인_사료 탭`, `메인_타임딜 없을 때`) |
| `ui/home-view.test.tsx` | 탭에 따라 화면이 바뀌는지, 상태 체크가 무엇을 약속하는지 본다 |
| `model/category.ts` | 카테고리 탭 URL 값·라벨·정규화. 서버 페이지(`page.tsx`)도 같이 써서 `"use client"`가 아닌 이 파일에 둡니다. 백엔드 `CategoryCode` 매핑은 `entities/product`가 갖고 있습니다(#390) |
| `model/category.test.ts` | 정규화를 봅니다 |
| `model/sort.ts` | 정렬 값·라벨·백엔드 `ProductSort` 매핑·정규화 |
| `index.ts` | 공개 API |

## 라우트

```text
/?category=all|food|snack|supplement&sort=<정렬>
```

## 탭에 따라 화면이 통째로 다르다

- **전체** — 골라주는 화면이다. 프로모션 배너, 아이 고르기, 맞춤 상품, 상태 체크, 타임딜
- **사료·간식·영양제** — 2열 상품 격자와 정렬

같은 화면의 필터가 아니라 다른 구성이라 조건부로 나눠 그린다.

## 종류·정렬은 서버가 준 값으로 그린다(#560)

`page.tsx`가 주소를 정규화한 `category`·`sort`를 목록 Promise와 **같은 렌더에서** 넘기고, 화면 구성·탭 표시·그리드 조건을 모두 그 값으로 그립니다. 탭과 정렬을 바꾸면 `router.push`(종류)·`router.replace`(정렬)로 주소를 바꾸고, 서버가 다시 그릴 때까지(`useTransition`의 `isPending`) 어느 탭이든 격자 뼈대를 보입니다. 탭 표시는 응답이 와야 옮겨 갑니다.

**nuqs(`shallow: false`)를 쓰지 않는 이유.** nuqs는 history API로 주소를 먼저 바꾸고 서버 요청을 따로 겁니다. 그 전환이 끝나기 전에 뒤로가면 `/`를 그린 앞뒤로 "이전 화면 그대로 주소만 사료로 바뀐 상태"가 늦게 커밋되고, nuqs 값은 `food`에 남았습니다. 주소는 `/`인데 화면은 사료 탭 모양(정렬 + 전체용 빈 목록)에 멈췄고 새로고침해야 풀렸습니다. 느린 CI 러너에서 E2E가 계속 흔들린 원인입니다. 느린 CPU(3배)에서 첫 화면 직후 누르면 매번 재현되어 `home.server-fetch.spec.ts`가 그 모양으로 지킵니다.

라우터 이동은 응답이 와야 주소가 바뀝니다. 그래서 **뼈대가 보이는 동안 뒤로가면 이 화면에 들어오기 전 화면으로 갑니다.** 앱의 다른 링크 이동과 같습니다.

## 가로 목록은 캐러셀이 아니다

맞춤 상품·상태 체크·타임딜은 손으로 밀어서 넘긴다. 저절로 넘어가지 않는다 — 디자인팀이 정한 것이다. 읽는 도중에 내용이 바뀌면 방해가 된다.

`shared/ui/scroll-row`를 쓴다. 목록 자체에 `tabIndex`를 주지 않는다. 칸 안이 모두 링크라 Tab으로 넘어가면 브라우저가 그 자리로 스크롤한다.

## 상태 체크가 이 서비스의 핵심이다

"최근에 구매한 상품, 아이는 어때요?"에서 반응을 받아 다음 추천에 반영한다. 시트 마지막에 **"(고른 아이 이름)의 다음 추천 적합도에 반영할게요"**를 적는 것은 그 약속을 보이게 하기 위해서다.

"아직 판단하기에는 일러요"도 답으로 받는다. 억지로 고르게 하면 값이 흐려진다.

**칸은 반응을 남길 수 있는 실제 구매다(#494).** 마이페이지 아이 관리의 제품 탭과 같은 `GET /reviews/feedbacks/pending`(`useQueryPendingFeedbacks`)이고, 고른 반응은 `useMutateSubmitFeedback`으로 서버에 간다. 답한 항목은 서버가 목록에서 뺀다. 전에는 누구에게나 같은 목데이터 두 개가 뜨고 반응이 서버에 가지 않았다.

- **로그인했을 때만 부르고, 남길 반응이 없으면 칸째 그리지 않는다.** Figma 메인 시안 15장 모두 이 칸이 있고 빈 모습(빈 상태 모음 포함)은 없다 — PD 확인거리다.
- **받는 동안 뼈대를 그리지 않는다.** 아이 줄과 달리 구매확정 뒤 며칠이 지난 사람에게만 있는 칸이라, 뼈대를 그렸다 지우면 칸이 없는 대부분의 사람에게 아래 구역이 한 번 밀린다. 받지 못하면 그 자리에서 알리고 다시 받는다.
- **시안의 "구매 후 N일"·"N번째 구매" 뱃지는 그리지 않는다.** 응답에 값이 없다. 지어낸 숫자를 보이면 반응의 근거가 거짓이 된다.
- **반응의 아이는 항목의 `petId`, 없으면 메인에서 고른 아이다.** 2026-09-23부터 주문에 아이가 필수라(주문 서비스 `CreateOrderRequest.petId`) 그 전 주문만 `null`이다. 항목의 아이가 목록에 없으면(지운 아이) 시트는 "우리 아이"로 묻는다 — 고른 아이 이름으로 떨어지면 다른 아이에게 묻게 된다.
- **다시 시도하는 동안에도 오류 칸을 지킨다.** 받아 둔 것 없이 실패한 뒤 다시 부르면 조회가 오류를 비우고 처음 받는 중으로 돌아간다. 훅의 `isRetrying`이 그 동안을 알려 칸이 사라졌다 돌아오지 않는다(#498 점검).

## 주황은 임시다

시안의 주황은 브랜드 컬러가 아니다. `--brand` 토큰 한 곳에 담아 두었으므로 색이 정해지면 `globals.css`의 그 두 줄만 갈아끼운다.

## 개발용 화면 목록은 옮겼다

메인이 `/`를 차지하면서 만들어 둔 화면 목록은 `/dev/screens`로 갔다. 자리 표시 화면이 남아 있는 동안은 그 목록으로 확인하는 편이 빠르다.

## 카테고리 그리드·타임딜 미리보기는 실제 API로 연동했다(#289)

`app/page.tsx`가 서버에서 `entities/product`의 `getProducts`·`getTimeDeals("ACTIVE")`를 조회해 Promise로 넘기고, `home-view.tsx`의 `ProductGrid`·`TimeDealPreview`가 각각 `use()`+`Suspense`로 그 결과만 대기합니다. "더 보기"는 브라우저에서 같은 `getProducts`를 커서로 이어 부릅니다.

**타임딜 미리보기 카드는 딜 아이템 번호를 들고 상세로 갑니다**(`?dealItem=`). 딜가는 일반 상품 상세에 오지 않아, 번호 없이 가면 상세가 정가를 보이고 정가로 담깁니다(#484).

**정렬 UI를 백엔드 5종(`RECOMMEND`·`POPULAR`·`REVIEW`·`PRICE_ASC`·`PRICE_DESC`)에 맞춰 바꿨습니다.** 기존 목업엔 최신순·별점순이 있었지만, Figma("메인_사료 탭_드롭다운")를 직접 확인해 보니 펼쳐진 옵션 목록 자체가 시안에 없고 닫힌 상태("추천순")만 있었습니다 — 근거 없이 채워져 있던 목업이라 백엔드 계약값으로 교체했습니다(`search-result`와 같은 5개 값).

**카테고리 매핑은 `entities/product`가 갖고 있습니다.** `getProducts`는 백엔드 `CategoryCode`(`FOOD`·`TREAT`·`SUPPLEMENT`)만 받습니다 — API 함수가 화면의 URL 값(`food`·`snack`·`supplement`)을 알면 API 계층이 화면 상태에 결합되기 때문입니다. `snack→TREAT`는 단순 대문자 변환이 아닙니다(`CategoryCode.java`로 직접 확인). 좋아요 화면도 같은 매핑을 쓰게 되면서(#390) `entities/product/model/category.ts`로 내렸습니다 — 여러 화면이 쓰는 값이라 한 곳에 둡니다.

**적합도 배지는 카테고리 그리드에서 뺐습니다.** 실제 `ProductCardResponse`엔 적합도(matchScore) 필드가 없습니다(`search-result`와 같은 공백). 정가는 백엔드가 `originalPrice`를 주게 되어 Figma 시안(1758-69075)대로 취소선 정가와 서버 할인율을 그립니다 (#458).

**카테고리 그리드 카드에 찜 하트와 별점 줄이 있습니다(#534).** 하트는 검색 결과·함께 보면 좋은 상품과 같은 `features/toggle-wishlist`의 `CardHeartButton`이고, 찜 여부는 전체 찜 목록(`useWishedProductIds`)에서 옵니다. 시안(사료 1758-69075·간식 1758-69126·영양제 1758-69151)은 원판 없는 24px 흰 하트인데, 다른 목록과 같은 원판(32px) 하트를 쓰고 원판을 8px 안쪽에 두어 하트 자리만 시안(모서리에서 12px)에 맞췄습니다 — 원판을 둘지는 PD 확인거리입니다. 별점은 값이 아니라 후기 수로 가르고, 후기가 없으면 시안대로 회색 별에 "-"입니다.

**칸(`li`)을 flex로 두지 않습니다.** 카드에 `flex-1`을 주던 동안 flex 항목의 최소 폭이 이름 전체 길이가 되어, 긴 이름의 카드가 옆 칸을 덮고 사진도 정사각형 칸보다 커졌습니다(QA HM-009·HM-011, #534).

**"AI가 골라주는 맞춤 상품" 캐러셀은 이번 라운드에 연동하지 않았습니다.** `petId`를 백엔드가 받기만 하고 실제 조회에 반영하지 않고(`ProductListCriteria`에 필드 자체가 없음), `RECOMMEND` 정렬도 `POPULAR`와 완전히 같은 동작이라(`resolveEffectiveSort()`) 개인화가 실제로 동작하지 않습니다 — `/recommendations`와 같은 이유로 제외했습니다. 재연동 조건은 후속 이슈로 남깁니다.

## 아이 고르기 줄은 실제 목록이다(#470)

마이페이지와 같은 `GET /members/me/pets` 목록을 받는다. 예시 아이(소리·냥이)를 쓰던 동안 화면마다 이름이 달랐다(QA 1차). 고르기 전에는 기본 아이이고, 받는 동안은 원 자리를 뼈대로 잡는다. 로그인하지 않았으면 부르지 않고 줄을 그리지 않으며, 제목은 "AI가 골라주는 우리 아이 맞춤 상품"으로 읽는다. 맞춤 상품과 적합도는 아직 목업이다(#384).

- **로그인 여부를 모르는 동안도 뼈대다.** 이 화면은 서버가 그리는데 서버는 로그인을 모른다(`useSessionState`가 `null`). 로그아웃 모양으로 그려 두면 하이드레이션 뒤 아이 줄이 끼어들며 아래 구역이 밀려서, 모를 때도 뼈대로 자리를 잡는다. 로그아웃 방문자는 그 뼈대가 한 번 접힌다 — 아이 등록이 전제인 서비스라 로그인한 쪽을 지킨다
- **아이가 0마리면 "추가" 칸만 남긴다.** 목록을 못 받았으면(실패) 줄을 비운다
- **"더보기"는 고른 아이를 들고 간다**(`/recommendations?pet=…`). 안 들고 가면 추천이 기본 아이로 열려 두 화면의 아이가 달라진다

## 태블릿·웹 폭은 이 화면이 직접 진다(#496)

**홈은 `(constrained)` 그룹 밖에 있는 첫 화면이다.** 라우트가 `src/app/page.tsx`로 나와 있고, 폭은 `home-view.tsx`의 최상위 래퍼가 `mx-auto w-full max-w-300`으로 정한다.

| 구간 | 콘텐츠 |
| --- | --- |
| 0 ~ 767 | 뷰포트 전체 폭 |
| 768 ~ 1199 | 뷰포트 전체 폭 |
| 1200 ~ | **1200px에서 멈추고 가운데 선다** |

**1200은 브레이크포인트가 아니라 최대 폭이다.** 실제 전환점은 `md`(768)과 `lg`(1024) 둘뿐이다. 거터 20px은 컨테이너가 아니라 섹션이 가진다 — 지금처럼 섹션마다 `px-5`·`pl-5`를 단다.

헤더·카테고리 탭·하단 탭바가 모두 이 래퍼 안에 있어 함께 맞춰진다. `BottomNav`가 `fixed`가 아니라 `sticky`라 흐름 안에 있기 때문이다.

**가로 스크롤 줄은 손대지 않는다.** 시안의 카드가 폭 고정이고 구역마다 다르다 — 맞춤 상품 208px, 타임딜 160px. 화면이 넓어지면 카드가 커지는 것이 아니라 더 많이 보인다.

**격자 열 수는 임시다.** `grid-cols-2 md:grid-cols-3 lg:grid-cols-4`로 1200에서 카드가 281px이 되게 잡았다. **받은 홈 시안이 전체 탭뿐이라 이 격자가 나오는 사료·간식·영양제 탭 시안이 없다** — PD가 열 수를 확정하면 맞춘다.

**이미지 `sizes`는 실제 표시 폭을 적는다.** 배너는 1200에서 1160px, 격자 카드는 281px이다. 기둥이 넓어졌는데 `sizes`가 옛 420px 전제로 남으면 Next가 작은 후보를 골라 이미지가 뭉개진다.

## 아직 없는 것

- 배너가 한 장이다. 배너 API가 없어 시안 배너 이미지(`public/images/home/promo-banner.webp`, 1708:22742를 2배로 내보냄)를 예시로 둔다(#504). 이미지 안의 남은 시간(02:14:27)과 "매주 목요일 밤 12시"는 시안 문구 그대로라 멈춰 있다. 점은 여럿임을 알리는 자리로만 그렸고 넘기지는 못한다
- "AI가 골라주는 맞춤 상품" 캐러셀이 목업입니다 — `/recommendations`와 함께 개인화 계약이 갖춰지면 후속 이슈로 연동합니다
- 배포 환경변수(`API_BASE_URL_INTERNAL`)는 로컬 값만 확인했습니다. 실제 GitOps 주입은 별도 확인이 필요합니다
