## 라우트

```text
/cart  장바구니
```

**경로는 임시다.** 삭제 확인은 같은 화면의 상태라 라우트를 나누지 않았다.

## 서버와 주고받는 것

```text
GET    /carts                              담은 것 전부
PATCH  /carts/items/{itemType}/{itemId}    { delta: ±n }
DELETE /carts/items/{itemType}/{itemId}
GET    /time-deals/items/{timeDealItemId}  타임딜 줄의 상품 번호 (공개 API)
```

**수량은 바뀐 값이 아니라 증감을 보낸다.** 스테퍼는 바뀐 값을 들고 있으므로 화면이 이전 값과의 차를 계산한다. 증감이라 연달아 눌러 요청이 여러 번 나가도 서버에서 합쳐진다 — 그래서 응답을 기다리지 않고 먼저 그릴 수 있다.

**줄을 가리키는 키가 `itemType`+`itemId` 둘이다.** 하나로 묶는 `cartItemKey()`를 써서 React key와 고른 목록에 넣는다. 세 경로 모두 그 둘로 줄을 가리키므로 다른 식별자는 필요 없다.

**수량 변경은 응답 본문을 기대하지 않는다.** 명세가 약속하는 것은 `200 OK`뿐이라 바뀐 값은 다시 조회해서 맞춘다.

**서버 컴포넌트로 두지 않는다.** 토큰이 클라이언트 저장소에 있어 서버에서 `Authorization`을 붙일 수 없고, 사람마다 내용이 달라 캐시할 것도 아니다.

**변경 실패 알림은 이 슬라이스가 하지 않는다.** `AppProviders`의 `MutationCache.onError`가 모든 변경 실패를 토스트로 알린다. 훅은 되돌리기만 맡는다. 조회 실패는 토스트 대상이 아니라 화면에서 직접 보여준다.

## 합계를 세는 규칙

고른 상품만 더한다. **하나도 고르지 않으면 금액 줄을 아예 보여주지 않고** 결제하기가 잠긴다 — 0원만 늘어놓아도 알려주는 것이 없고 고르라는 신호가 흐려진다. 시안도 그렇게 그려져 있다.

화면은 아무것도 고르지 않은 상태(`0/3`)로 시작한다. **살 수 없는 줄은 셈에서 뺀다** — 넣으면 "전체선택"이 끝까지 차오르지 않는다.

## 고른 줄은 이 브라우저에 남는다

`useState`로 들던 동안 결제 화면에 갔다 뒤로 오거나 탭을 닫았다 열면 `0/9`로 풀렸다(QA No.23·24). 지금은 **고른 줄의 키(`NORMAL:1`)만** Zustand `persist`(localStorage)에 남긴다. 이름·가격·재고는 복사하지 않는다 — 서버 값을 옮기면 품절돼도 옛 값이 남는다(AGENTS 5.1). 저장소 감싸개와 복원 검증은 최근 본 상품(`features/recently-viewed`)과 같은 방식이다.

- **들어올 때 지금 살 수 있는 줄과 겹치는 키만 고른 것으로 본다.** 그사이 빠지거나 품절된 줄의 키는 셈에 들지 않고, 다음에 고를 때 걷힌다(쓸 때는 겹친 목록에서 만들어 저장한다).
- **처음 담긴 줄은 고르지 않은 상태다.** 시안이 `0/3`으로 시작한다.
- **뺀 줄은 고른 목록에서도 뺀다.** 남겨 두면 같은 상품을 다시 담았을 때 골라진 채로 보인다.
- **결제한 줄은 따로 비우지 않는다.** 완료 화면이 결제한 줄을 장바구니에서 빼므로(#457) 들어올 때 겹치지 않아 저절로 빠진다. 결제가 실패·취소되면 고른 것이 그대로 남는다.
- 기기·브라우저마다 따로다. 로그인 계정과 묶지 않는다 — 다른 계정으로 들어와도 키가 같은 줄만 겹친다.

## 줄을 누르면 상세로 간다

이름 링크(`ui/cart-item-link.tsx`)의 `::after`가 줄(`li`)을 덮어 사진·가격을 눌러도 상세로 간다(QA No.9). 체크박스·빼기·수량은 링크 안에 두면 "링크 속 버튼"이 되므로 링크 밖에 두고 `relative z-10`으로 덮개 위에 올린다.

- 일반 줄은 `/products/{itemId}`다. 줄 번호가 곧 상품 번호다.
- **타임딜 줄은 상품 번호를 모른다.** 장바구니 응답에 딜 아이템 번호만 온다(백엔드 `CartItemResponse`). 공개 API인 딜 상세에서 상품 번호를 받아 딜가로 보이는 주소(`/products/{상품}?dealItem={딜 아이템}`, #484)로 보낸다. 딜 줄마다 한 번 나가고 바로 구매와 캐시를 함께 쓴다.
- 갈 곳을 모르면 이름만 두고 링크를 걸지 않는다 — 이름이 안 오는 줄(`NOT_FOUND`·`TEMPORARILY_UNAVAILABLE`), 끝난 딜(`DEAL_ENDED`), 딜 상세를 받지 못한 줄이다. **끝난 딜은 딜 상세를 부르지도 않는다** — 진행 중·예정 딜만 보여 주는 API라 404가 확실한데, 부르면 브라우저 콘솔에 실패가 찍혀 화면 스모크(`screens.spec.ts`)가 오류로 센다.

## 할인과 품절

할인 줄(`discountRate > 0`)은 정가 취소선을 판매가 위에, 할인율을 판매가 왼쪽에 둔다(QA No.10). 시안은 할인 없는 상품만 그려 상품 카드(`product-grid-card`)의 모양을 따랐다. 할인이 없는 줄도 `originalPrice`가 판매가와 같은 값으로 온다.

품절 줄(`OUT_OF_STOCK`)은 사진 왼쪽 아래에 "품절" 표시를 얹는다(QA No.21). 색은 타임딜 목록의 품절 배지(1905-32428)와 같다. 살 수 없는 줄은 모두 사진을 50%로 흐린다 — 품절 상품 상세의 대표 사진(1702:19206)과 같은 값이다. 흐림은 사진에만 건다. 감싼 칸에 걸면 쌓임 맥락이 생겨 체크박스가 줄을 덮는 링크 아래로 깔린다.

서버가 주는 `subtotal`과 `totalAmount`는 쓰지 않고 `price × quantity`로 센다. 고른 것만 더해야 하고, `totalAmount`는 수량을 방금 바꿨을 때 다시 받기 전까지 옛 값이다. 줄 합계(`subtotal`)는 수량을 바꾸면 캐시에서 함께 고친다 — 결제 화면이 그것을 더하기 때문이다 (#427).

**배송비는 3,000원 고정이다.** 응답에 `deliveryFee`가 없다. **백엔드가 까닭을 확인해 줬다** — "MVP 단계에선 배송비는 정적으로 고정한다는 정보 기반으로 반환하지 않았다"(2026-09-21). 고정값이 맞다. 시안이 19,900원 주문에 배송비 0원으로 그려 둔 것만 PD 확인이 남는다.

## 살 수 없는 줄

**살 수 없는 줄이라고 내용이 늘 비지는 않는다.** 서버 `unavailableWithoutInfo`가 쓰이는 둘(`NOT_FOUND`·`TEMPORARILY_UNAVAILABLE`)만 이름·사진·금액이 `null`이고, 상품은 있는데 못 사는 경우(`OUT_OF_STOCK`·`DISCONTINUED`·`DEAL_ENDED`)는 **그 값들이 그대로 온다**(`unavailableWithInfo`). 그래서 내용 필드가 nullable이다. 어느 쪽이든 고를 수 없게 막고 `unavailableReason`을 우리 문구로 바꿔 보여준다 — **이름이 오면 이름 아래에, 안 오면 이름 자리에** 둔다. 빼기는 남겨 둔다 — 지울 길이 없으면 장바구니에 계속 걸린다.

**이 상태는 시안에 없다.** 새로 그리지 않고 화면에 있는 것만 썼다. 까닭 코드 다섯(`NOT_FOUND`·`TEMPORARILY_UNAVAILABLE`·`OUT_OF_STOCK`·`DISCONTINUED`·`DEAL_ENDED`)을 모두 우리 문구로 옮겼다.

## 아직 없는 것

- 2026-09-09에 요청한 응답 필드는 정리됐다. 옵션은 없는 것으로 합의했고(9/14), 배송비는 MVP에서 고정이라 응답에 넣지 않는다(9/21 백엔드) — 화면은 3,000원 고정이다. `brandName`과 쿼리 파라미터 `petId`는 여전히 없지만 지금 화면은 둘 다 쓰지 않는다
- 담기(`POST`)는 여기서 부르지 않는다. 상품 상세에서 담으므로 그 화면이 붙일 때 이 슬라이스에 더한다
- 삭제 확인창 문구는 와이어프레임 것을 유지했다. UI 시안(`cart_001_삭제하기`)이 제목과 설명에 같은 문구를 넣어 두어 더미로 보인다 — PD팀 확인 대기
- 옵션 변경은 2026-09-09 시안 수정에서 빠졌다. `cart_001_옵션변경` 프레임이 삭제되고 "페이지 삭제 및 옵션변경 버튼 삭제" 메모가 붙었다 (#137)
- 결제상세의 금액 줄 이름이 화면마다 다르다. 장바구니는 "판매가격"(`1568:63753`), 결제하기는 "상품 옵션", 주문 완료는 "판매 금액"이다. 화면마다 시안을 따른다
- 결제하기가 고른 줄을 `?items=NORMAL:1,TIME_DEAL:3` 꼴로 `/payment`에 넘긴다. 그전에는 셋 중 하나만 골라도 전체가 결제됐다 (#259)
- 비어 있을 때의 화면은 빈 장바구니 시안(`2022:157279`)대로 `EmptyState`로 그린다(#244). **"전체선택 (0/0)"과 "결제하기"는 잠근 채 남긴다** — 담은 뒤 무엇을 할 수 있는지 예상하게 PD팀이 일부러 둔 것이다 (2026-09-28, #448). "상품 둘러보기"는 메인(`/`)으로 간다 — 검색으로 보내던 것을 PM QA가 실패로 봤다(No.7, #563)
