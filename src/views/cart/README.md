# views/cart

담아 둔 상품을 고르고 수량을 바꾸거나 빼는 화면. UI 시안 `cart_001`과 그 두 상태(`_선택`·`_삭제하기`)에 대응한다.

| 파일 | 설명 |
| --- | --- |
| `api/cart.ts` | 장바구니 조회·수량 변경·빼기와 응답 타입(`Cart`·`CartItem`) |
| `api/use-query-cart.ts` | 장바구니를 가져오는 훅 |
| `api/use-mutate-cart-item.ts` | 수량 변경과 빼기. 낙관적 갱신과 되돌리기를 맡는다 |
| `ui/cart-view.tsx` | 장바구니. 삭제 확인창을 함께 가진다 (`cart_001`) |
| `ui/cart-skeleton.tsx` | 불러오는 동안 자리를 잡는 뼈대 |
| `ui/cart-view.test.tsx` | 무엇이 합계에 들어가는지, 고른 것이 없을 때 금액 줄이 감춰지는지 본다 |
| `index.ts` | 공개 API |

## 라우트

```text
/cart  장바구니
```

**경로는 임시다.** 삭제 확인은 같은 화면의 상태라 라우트를 나누지 않았다.

## 서버와 주고받는 것

```text
GET    /carts                              담은 것 전부
PATCH  /carts/items/{itemType}/{itemId}    { delta: ±n }
DELETE /carts/items/{itemType}/{itemId}
```

**수량은 바뀐 값이 아니라 증감을 보낸다.** 스테퍼는 바뀐 값을 들고 있으므로 화면이 이전 값과의 차를 계산한다. 증감이라 연달아 눌러 요청이 여러 번 나가도 서버에서 합쳐진다 — 그래서 응답을 기다리지 않고 먼저 그릴 수 있다.

**줄을 가리키는 키가 `itemType`+`itemId` 둘이다.** 하나로 묶는 `cartItemKey()`를 써서 React key와 고른 목록에 넣는다.

**서버 컴포넌트로 두지 않는다.** 토큰이 클라이언트 저장소에 있어 서버에서 `Authorization`을 붙일 수 없고, 사람마다 내용이 달라 캐시할 것도 아니다.

**변경 실패 알림은 이 슬라이스가 하지 않는다.** `AppProviders`의 `MutationCache.onError`가 모든 변경 실패를 토스트로 알린다. 훅은 되돌리기만 맡는다. 조회 실패는 토스트 대상이 아니라 화면에서 직접 보여준다.

## 합계를 세는 규칙

고른 상품만 더한다. **하나도 고르지 않으면 금액 줄을 아예 보여주지 않고** 결제하기가 잠긴다 — 0원만 늘어놓아도 알려주는 것이 없고 고르라는 신호가 흐려진다. 시안도 그렇게 그려져 있다.

화면은 아무것도 고르지 않은 상태(`0/3`)로 시작한다. **살 수 없는 줄은 셈에서 뺀다** — 넣으면 "전체선택"이 끝까지 차오르지 않는다.

서버가 주는 `subtotal`과 `totalAmount`는 쓰지 않는다. 고른 것만 더해야 하고, 수량을 방금 바꿨을 때 그 값들은 아직 옛 것이다.

**배송비는 3,000원 고정이다.** 응답에 `deliveryFee`가 없다. 시안은 19,900원 주문에 배송비 0원으로 그려져 있는데 무료배송 기준선이 생긴 것인지 시안 더미값인지 알 수 없어 PD·PM팀에 확인을 요청해 두었다.

## 살 수 없는 줄

`available: false`면 **이름·사진·금액이 전부 `null`로 온다.** 고를 수 없게 막고 `unavailableReason`을 우리 문구로 바꿔 한 줄 보여준다. 빼기는 남겨 둔다 — 지울 길이 없으면 장바구니에 계속 걸린다.

**이 상태는 시안에 없다.** 새로 그리지 않고 화면에 있는 것만 썼다. 명세에 나온 까닭 코드가 `DEAL_ENDED` 하나뿐이라 나머지는 기본 문구로 떨어진다.

## 아직 없는 것

- **`DELETE` 경로와 줄 식별자가 확정이 아니다.** 삭제 스키마가 명세에 없어 수량 변경과 같은 자원 경로로 뒀다. 조회 응답에는 `cartItemId`가 없는데 수량 변경 응답에는 있어, 어느 것이 줄을 가리키는 키인지 확인이 필요하다 (#214)
- 2026-09-09에 요청한 `brandName`·`optionLabel`·`deliveryFee`·`freeDeliveryThreshold`와 쿼리 파라미터 `petId`가 아직 응답에 없다
- 담기(`POST`)는 여기서 부르지 않는다. 상품 상세에서 담으므로 그 화면이 붙일 때 이 슬라이스에 더한다
- 삭제 확인창 문구는 와이어프레임 것을 유지했다. UI 시안(`cart_001_삭제하기`)이 제목과 설명에 같은 문구를 넣어 두어 더미로 보인다 — PD팀 확인 대기
- 옵션 변경은 2026-09-09 시안 수정에서 빠졌다. `cart_001_옵션변경` 프레임이 삭제되고 "페이지 삭제 및 옵션변경 버튼 삭제" 메모가 붙었다 (#137)
- 결제상세의 "상품 옵션" 줄에는 금액이 들어간다. 시안 세 화면이 모두 그렇게 부르고 있어 그대로 옮겼고, "상품 금액"이 맞는지 PD팀에 확인을 요청해 뒀다
- 결제하기가 `/payment`로 가지만 고른 상품이 함께 넘어가지 않는다. 화면 간 전달은 라우터 구조가 정해진 뒤에 붙인다
- 비어 있을 때의 화면은 `EmptyState`로 그려 두었으나 시안이 없다
