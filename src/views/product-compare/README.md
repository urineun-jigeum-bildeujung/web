## 라우트

`/compare` — `src/app/compare/page.tsx`

## 상태를 어디에 두었나

검색 화면에서 전달된 `slot`·`product`는 URL 쿼리로 읽는다. 상품 상세에서 `from=detail`과 함께 들어오면 현재 상세 목상품만 첫 자리에 담고 두 번째 자리는 비운다. 두 번째 상품을 검색할 때는 첫 상품 ID를 `first`로 전달해 돌아와도 첫 자리를 유지한다. 화면에 담긴 상품은 API 연동 전까지 컴포넌트 상태로 든다. 상품을 빼면 그 자리가 비면서 비교표가 사라진다.

**검색으로 갔다 오는 동안 반대쪽 자리는 `other` 쿼리로 들고 다닌다.** `/search`로 넘어가면 이 컴포넌트가 통째로 언마운트됐다 돌아올 때 재마운트되어, 반대쪽 자리의 상태를 기억할 방법이 URL밖에 없다. 예전엔 이걸 몰라서 반대쪽을 항상 화면 확인용 기본값(`MOCK_PRODUCTS`)으로 되돌렸는데, 방금 고른 상품이 우연히 그 기본값과 같은 id면 두 자리가 같은 key를 가져 React가 충돌 경고를 내고 자리 하나가 사라지는 사고가 났다(#245). `other=<id>`는 반대쪽 자리의 실제 상품을, `other=none`은 그 자리가 실제로 비어 있었다는 뜻이다 — 아예 안 주면(주소를 손으로 입력해 확인할 때 등) 화면 확인용 기본값을 보여준다.

## 짚어둘 것

**적합도가 갈리면 우열을 크기·색으로 가른다.** 높은 쪽은 22px 브랜드색, 낮은 쪽은 16px 회색(`CompareSlot`). 동점이거나 한쪽이라도 재지 못했으면(`matchScore: null`) 우열 없는 기본 크기다 — Figma에 없는 상태라 임의로 정했다.

**"맞춤 분석" 콜아웃은 실제 담긴 두 상품 이름으로 문장을 만든다.** 시안(1568-70534)의 예시 문구를 그대로 박으면 화면에 없는 상품·아이 이름이 뜬다. `/products/compare`가 API 명세상 AI 대기 상태라 실제 AI 분석이 붙기 전까지 쓰는 임시 함수(`buildAiAnalysis`)다.

**장바구니 담기는 토스트만 띄운다.** `entities/cart`에 "새로 담기" API가 아직 없어(변경·삭제만 있다) `deals-view`·`product-detail-view`와 같은 방식으로 담겼다고만 알린다.

**머리말은 `PageHeader`에 `title`을 준다.** 예전엔 `leading="none"`만 있고 `title`이 없어 뒤로가기와 "상품비교" 제목이 통째로 빠져 있었다(1568-70276). 오른쪽 알림·장바구니 아이콘도 react-icons가 아니라 `home-view`와 같은 방식(`Icon` 세트, `size-7`, `after:` 의사요소로 탭 영역 확장)으로 맞추고, 장바구니가 #214로 이미 나와 있어 `/cart`·`/mypage/notifications`로 실제 링크를 건다.

## 아직 없는 것

- 비교 항목 아홉 개는 목 데이터고, 정확히 1번·2번 상품 조합의 실측값이다(`getRows`). 그 조합이 아니면 고르지도 않은 상품의 스펙을 보여주지 않으려고 표 대신 "준비 중" 안내를 보여준다 — API 계약이 나오면 이 화이트리스트(`SUPPORTED_FOOD_PAIR`)와 `getRows`는 사라지고, 어떤 조합이든 실제 값을 내려받는다
- "맞춤 분석" 문구는 실제 AI 분석이 아니다. `/products/compare` API가 붙으면 `buildAiAnalysis`는 사라진다
- **상세에서 고른 아이가 비교 화면까지 이어지지 않는다.** `product-detail-view`에서 아이를 바꾸면(예: 점수가 없는 "냥이") `PET_MATCHES`로 실제 적합도가 바뀌는데, "비교하기"로 넘어갈 때 이 정보를 전달하지 않아 비교 화면은 항상 `MOCK_DETAIL_PRODUCT.matchScore`(소리 기준 92점)를 쓴다. 상세 상품 점수만 따로 넘겨도 반쪽짜리 해결이다 — 비교 상대 상품(`PICKABLE`)의 `matchScore`도 애초에 특정 아이 기준이라고 명시된 적이 없는 고정값이라, 상세 쪽만 고치면 서로 다른 아이 기준의 점수를 나란히 비교하게 된다. **API 연동 자체로 저절로 해결되지 않는다** — 연동 작업은 선택된 아이 id를 기준으로 비교하는 두 상품의 적합도를 함께 조회하도록 설계해야 한다. Figma에 없는 "소리 기준" 표시 같은 새 UI를 이번 PR에서 임의로 만들지 않는다
- 장바구니 담기 mutation이 없다. `views/deals`·`views/product-detail`도 같은 이유로 실제 요청 없이 토스트만 띄운다 — 실제 mutation이 붙을 때 세 화면을 함께 정리한다
