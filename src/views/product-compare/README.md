# views/product-compare

두 상품을 항목별로 견주는 화면. UI 시안 기준(#245, comp_001·comp_001_에러·comp_001_empty)이다.

| 파일 | 설명 |
| --- | --- |
| `ui/product-compare-view.tsx` | 두 자리와 비교 영역을 조립한다. 자리의 상품은 상세 조회로 채우고, 한쪽이라도 비면 비교 영역을 감춘다. "장바구니 추가"는 수량 시트를 열어 실제로 담는다 |
| `ui/product-compare-view.test.tsx` | 빈 칸 시작, 주소의 상품 번호로 자리 채우기, 받는 중·실패, 검색 왕복, 빼면 주소도 비우기, 장바구니 담기와 헤더 수 갱신, 품절이면 담기 막기를 본다 |
| `index.ts` | 공개 API |

## 라우트

`/compare` — `src/app/compare/page.tsx`

## 상태를 어디에 두었나

**어느 자리에 어떤 상품이 있는지(번호)는 화면이, 상품 내용은 서버 상태가 든다.** 검색 화면에서 전달된 `slot`·`product`는 URL 쿼리로 읽어 자리에 번호를 넣고, 이름·가격·이미지는 `useQueryProductDetails`(`entities/product`)가 상품 상세로 받는다(#535). 상품을 빼면 그 자리가 비면서 비교 영역이 사라진다.

**빼면 주소도 남은 자리로 바꾼다(`router.replace`).** 자리 번호는 마운트할 때 한 번만 주소에서 읽는다. 예전엔 빼도 주소에 번호가 남아, 검색에서 뒤로 오거나 새로고침해 다시 마운트되면 뺀 상품이 되살아났다(QA HM-000). 남은 자리는 `slot`·`product`·`other` 형식으로 적고, 둘 다 비면 `/compare`만 남긴다. 상세에서 온 흐름도 `from=detail` 대신 `other`로 적는다 — 검색 화면은 둘을 똑같이 "반대쪽 자리에 이미 있는 상품"으로만 읽는다. 빼기는 화면 이동이 아니라 기록을 쌓지 않는다.

**고른 상품이 없으면 두 자리 모두 빈 칸으로 시작한다.** 예전엔 주소에 상품이 없으면 화면 확인용 예시 상품 둘(`MOCK_PRODUCTS`)을 채워, 담지 않았는데 담겨 있고 빼고 다른 화면에 다녀와도 되살아났다(QA HM-000).

**검색에서 고른 번호는 실제 상품 번호다.** 예전엔 그 번호를 목업 맵(`PICKABLE`, 키 "1"~"8")에서 찾아, 검색이 돌려준 33 같은 번호는 자리가 빈 채로 남고 1~8은 이름이 다른 목업 상품이 들어갔다(QA CP-022). 없어진 상품(404)은 빈 자리로 두고, 다른 실패는 그 자리에 다시 시도를 보인다.

상품 상세에서 `from=detail`과 함께 들어오면 그 상품만 첫 자리에 담고 두 번째 자리는 비운다. 두 번째 상품을 검색할 때는 첫 상품 번호를 `first`로 전달해 돌아와도 첫 자리를 유지한다.

**검색으로 갔다 오는 동안 반대쪽 자리는 `other` 쿼리로 들고 다닌다.** `/search`로 넘어가면 이 컴포넌트가 통째로 언마운트됐다 돌아올 때 재마운트되어, 반대쪽 자리의 번호를 기억할 방법이 URL밖에 없다. 예전엔 이걸 몰라서 반대쪽을 항상 화면 확인용 기본값으로 되돌렸는데, 방금 고른 상품이 우연히 그 기본값과 같은 id면 두 자리가 같은 key를 가져 React가 충돌 경고를 내고 자리 하나가 사라지는 사고가 났다(#245). `other=<번호>`는 반대쪽 자리의 실제 상품을, `other=none`은 그 자리가 실제로 비어 있었다는 뜻이다.

## 짚어둘 것

**"장바구니 추가"는 수량 시트(`ProductOptionSheet`)를 열고 `useMutateCartItem`으로 담는다(#535).** 예전엔 담지 않고 토스트만 띄워 시트도 없고 헤더 장바구니 수도 그대로였다(QA CP-006·007·010). 담기가 성공하면 그 훅이 장바구니 조회를 다시 받아 헤더 `CartLink`의 수가 바뀐다. 거부되면 시트가 열린 채 남고 실패 알림은 전역 토스트가 맡는다. 담는 식별자는 상품 상세와 같은 규칙이다 — 일반 상세 응답은 딜 아이템 번호를 비워 주므로 지금은 늘 `NORMAL`+상품 번호다.

**품절이면 "장바구니 추가"를 막는다.** 상품 상세 응답의 `soldOut`을 자리에 넘기고, `CompareSlot`이 버튼을 비활성으로 두고 글자를 "품절"로 바꾼다. 예전엔 품절 상품도 시트가 열려 담기를 보냈고 서버가 거부해야 알 수 있었다. 시안에 비교 자리의 품절 모양이 없어 줄을 늘리지 않는 가장 단순한 모양으로 두었다 — 안내 줄을 따로 두면 두 자리의 버튼 줄이 어긋난다. PD 확인 전이다.

**적합도가 갈리면 우열을 크기·색으로 가른다.** 높은 쪽은 22px 브랜드색, 낮은 쪽은 16px 회색(`CompareSlot`). 동점이거나 한쪽이라도 재지 못했으면(`matchScore: null`) 우열 없는 기본 크기다 — Figma에 없는 상태라 임의로 정했다. 지금은 적합도 API가 없어 실제 상품이 모두 null이라 우열이 뜨지 않는다.

**"맞춤 분석" 콜아웃은 실제 담긴 두 상품 이름으로 문장을 만든다.** 시안(1568-70534)의 예시 문구를 그대로 박으면 화면에 없는 상품·아이 이름이 뜬다. `/products/compare`가 API 명세상 AI 대기 상태라 실제 AI 분석이 붙기 전까지 쓰는 임시 함수(`buildAiAnalysis`)다. 두 상품 모두 적합도를 모르면 "두 상품 모두 아직 적합도를 재지 못했어요."라고 한다.

**머리말은 `PageHeader`에 `title`을 준다.** 예전엔 `leading="none"`만 있고 `title`이 없어 뒤로가기와 "상품비교" 제목이 통째로 빠져 있었다(1568-70276). 오른쪽 알림·장바구니 아이콘도 react-icons가 아니라 모든 헤더와 같은 공용 슬롯(`HeaderIconLink`, 시안 33×32 슬롯에 28px 아이콘, #513)으로 맞추고, 장바구니가 #214로 이미 나와 있어 `/cart`·`/mypage/notifications`로 실제 링크를 건다.

## 아직 없는 것

**자리의 이름·가격·이미지·품절만 실제 API에서 온다. 나머지는 비교용 API가 없어 채우지 못한다.**

- **항목별 비교표(`comp_001`의 아홉 항목)를 그리지 않는다.** 성분·영양 비율·칼로리 같은 값을 주는 API가 없다. 예전 목데이터 표는 목업 상품 1·2번(과 영양제 한 쌍)의 값이라, 실제 상품 이름 아래 붙이면 고르지도 않은 상품의 스펙을 그 상품 것처럼 보여준다(#245 후속에서 같은 이유로 조합을 막았다). 그래서 두 자리가 다 차면 맞춤 분석 아래에 "준비 중" 안내를 보인다. 값이 오면 `CompareTable`(`entities/product`)에 그대로 넣는다
- **종류(`kind`)를 모른다.** 상품 상세 응답에 분류가 없어 `null`이고, 모르면 종류로 막지 않는다. 그래서 시안 comp_001_에러("건식은 건식끼리") 안내는 지금 뜨지 않는다. 응답에 분류가 오면 `toCompareProduct`만 고치면 된다
- **적합도(`matchScore`)를 모른다.** 비교용 적합도 API가 없어 `null`이다. 연동할 때는 상세에서 고른 아이 id를 기준으로 두 상품의 적합도를 함께 조회하도록 설계해야 한다 — 서로 다른 아이 기준의 점수를 나란히 두면 비교가 성립하지 않는다. Figma에 없는 "소리 기준" 표시 같은 새 UI를 임의로 만들지 않는다
- "맞춤 분석" 문구는 실제 AI 분석이 아니다. `/products/compare` API가 붙으면 `buildAiAnalysis`는 사라진다
