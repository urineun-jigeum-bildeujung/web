# entities/member

로그인한 보호자 자신의 정보. 여러 화면이 같은 값을 본다.

| 파일 | 설명 |
| --- | --- |
| `api/profile.ts` | 내 정보 조회·수정·탈퇴 요청과 `MemberProfile` 타입 |
| `api/profile.test.ts` | 무엇을 부르는지, 고칠 것만 보내는지 |
| `api/use-query-my-profile.ts` | 내 정보를 가져오는 훅 |
| `api/use-mutate-my-profile.ts` | 고친 값을 저장하고 조회를 무효화하는 훅 |
| `api/use-mutate-withdraw.ts` | 탈퇴하고 기기의 흔적을 지우는 훅 |
| `index.ts` | 공개 API |

## 왜 엔티티인가

**한 화면의 값이 아니다.** 마이페이지 홈의 프로필 카드, 내 정보 화면의 다섯 줄, 닉네임 수정 화면이 같은 것을 본다. 뷰에 두면 어느 뷰가 원본인지 정할 수 없다.

## 짚어둘 것

**고칠 것만 보낸다.** `PATCH /members/me`는 전 필드가 선택이다. 닉네임만 고치는 화면이 이름·생년월일까지 실으면 고치지도 않은 값을 덮어쓴다.

**저장하면 조회를 무효화한다.** 하지 않으면 돌아온 화면이 옛 닉네임을 보여, 방금 고친 사람에게는 저장이 안 된 것으로 읽힌다.

**탈퇴는 실패하면 아무것도 지우지 않는다.** 로그아웃과 다른 점이다. 로그아웃은 서버 정리에 실패해도 기기의 토큰을 지운다 — 막으면 남의 기기에서 빠져나올 방법이 없다. 탈퇴는 계정이 살아 있는데 토큰만 비우면 쫓겨난 채로 탈퇴됐는지도 알 수 없다.

**로그인 화면으로 보내는 것은 여기가 아니다.** `clearTokens()`가 울리는 알림을 `SessionExpiryRedirect`가 받는다(#230).

## 아직 없는 것

`name`·`birth`는 서버가 주지만 **받는 자리가 화면에 없다.** 회원가입도 온보딩도 묻지 않아 늘 비어 온다. 시안에 그 입력 화면이 없어 PD 확인 대상이다(#64).

`image`는 `POST /members/me/profile-image/presigned-url`로 올린 뒤 `PATCH /members/me`에 실어 보낸다. 별도 이슈로 다룬다(#269).
