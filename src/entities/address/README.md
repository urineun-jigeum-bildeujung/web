# entities/address

배송 받을 곳. 마이페이지의 배송지 화면과 결제 흐름이 함께 쓴다.

**`views/` 안이 아니라 여기 있는 이유**는 세 슬라이스(`views/edit-address` · `views/checkout` · `views/addresses`)가 같은 것을 쓰기 때문이다. `views/` 안에 두면 같은 레이어 간 참조라 막힌다 (AGENTS.md 4절).

**목록 화면도 여기 있다.** 결제의 배송지 설정(`/payment/address`)과 마이페이지의 배송지 관리(`/mypage/address`)가 같은 목록을 그린다. 둘 다 `views/`라 한쪽에 두면 다른 쪽이 못 본다 (#329).

## 알아둘 것

**배송지를 고르는 API는 없다.** `/payment/address`는 목록에서 하나를 골라 `addressId`를 주문 생성(`POST /orders`)에 넘긴다. 서버에 "지금 고른 배송지" 같은 상태는 없다.

**집·회사는 서버에 없는 개념이다.** 종류를 내려주지 않으므로 아이콘은 화면이 `addressName`으로 고른다.

**그래도 목록은 집·회사 자리를 늘 잡는다**(시안 `paym_011` `1117:4825`). 그 이름으로 저장한 곳이 없으면 "상품을 배송받을 주소를 입력해 주세요." 빈 줄을 구분선 위 끝에 그리고, 누르면 `?name=`으로 이름을 채운 채 새 배송지 입력으로 간다. 배송지가 하나도 없으면 빈 줄 대신 빈 상태 문구를 보인다 — 그 경우의 시안은 없다 (#455).

**`deliveryNote`만 nullable이다.** 나머지는 등록할 때 빈 값으로 보내면 안 된다.

**요청사항 칸은 결제 화면과 배송지 폼이 같은 것을 쓴다** (QA No.174, #526). 보기 목록이 결제 화면에만 있고 배송지 폼은 적는 칸 하나라, 같은 요청을 두 화면에서 다르게 받았다. 값은 문자열 하나다 — 고른 보기의 문구이거나 직접 적은 글이다. 저장해 둔 글이 목록에 없으면 "직접 입력"을 고른 채로 열어 그 글을 보인다. 결제 화면은 첫 보기를 기본으로 두고, 배송지 폼은 요청사항 없는 배송지가 있어 고른 것이 없으면 안내 글자("요청사항을 선택해주세요")를 보인다.

**직접 적는 칸은 `maxLength`에 더해 값을 100자로 자른다** (QA No.175). 한글은 조합 중인 글자가 길이 제한을 거치지 않아 101자째가 들어왔고, 배송지 폼은 그 값을 검증에서 막아 입력 완료가 꺼진 채 남았다. 이모지처럼 두 단위로 된 글자가 100자 경계에 걸리면 반만 남기지 않고 통째로 뺀다(#526 리뷰).

**삭제는 함수만 있고 부르는 화면이 없다.** 지우는 자리가 `/mypage/address`인데 그 화면은 PD 시안 대기다.
