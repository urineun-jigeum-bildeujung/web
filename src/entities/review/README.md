## 왜 별점만 두지 않았나

같은 사료라도 4kg 말티즈와 30kg 리트리버의 후기는 다른 이야기다. 별점만 나열하면 그 차이가 사라져, 보호자가 자기 아이에게 적용할 수 있는지 판단할 수 없다. 품종·나이·체중을 이름 바로 아래에 두는 이유다.

## 아직 없는 것

계약이 부족하거나 정책이 안 정해진 것은 **임시로 지어내지 않고 닫아 둔다.**

- **아이 줄에 품종명이 없다.** 응답에 오는 것은 `breedId`뿐이고 이름은 `GET /pets/breeds`에만
  있는데, **그 조회가 인증을 요구해 비로그인으로 열리는 상품 상세에서 401이 난다.**
  백엔드가 리뷰 응답에 `breedName`을 싣거나 품종 조회가 공개되면 붙인다 — 어느 쪽이든
  고칠 곳은 `lib/pet-label` 하나다
- **재구매 배지를 그릴 수 없다.** 응답에 `repurchaseCount`가 없다. PD가 MVP로 확정해
  (2026-09-28) 백엔드에 요청해 둔 값이다
- 신고는 보낼 곳이 없다. 계약이 정해지면 잇는다

## 도움돼요

**누르면 화면이 먼저 바뀐다(낙관적 갱신).** 수가 하나 오르고 활성이 되며, 다시 누르면 풀리고 하나 내린다. 첫 눌림은 목록·상세 응답의 `liked`다. 이미 결과를 그려 두므로 대기 표시를 두지 않는다(AGENTS 5.8). 실패하면 그 후기만 누르기 전으로 되돌리고, 알림은 전역 `MutationCache` 토스트가 띄운다. 비로그인이면 요청을 보내지 않고 로그인 필요 토스트만 띄운다(#542) — 판단은 `useRequireSession` 하나다.

- **토글 응답의 본문을 읽지 않는다.** `PATCH /reviews/{id}/recommend`는 같은 요청이 켜고 끈다. 응답 모양을 확인하지 못해 본문에 기대지 않고, 요청이 모두 끝나면 서버 값으로 다시 맞춘다
- **상세는 다시 받고 목록은 낡았다고만 표시한다.** 추천순은 도움돼요 수로 줄을 세워, 누르자마자 목록을 다시 받으면 읽던 후기가 자리를 옮긴다. 목록은 다음에 열 때 서버 값으로 맞춰진다
- **새로고침 직후 첫 목록의 `liked`가 틀릴 수 있다.** 액세스 토큰은 메모리에만 있어 새로고침하면 사라지고, 공개 조회인 후기 목록은 401 없이 인증 없는 요청으로 끝나 서버가 `liked: false`를 준다. 그 상태에서 이미 누른 후기를 누르면 화면은 켜지는데 서버는 끈다. 사진 뷰어의 상세는 끝난 뒤 다시 받아 맞춰지지만 리뷰 탭 목록은 다시 열 때까지 어긋난다. 공개 조회 전에 토큰을 먼저 재발급하는 것은 세션 쪽 작업이라 이번에 하지 않았다
