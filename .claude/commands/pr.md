description: PR 올리기 — 검증 → 이슈 업데이트 → PR 생성(템플릿)
---

현재 작업을 PR로 올린다. `docs/conventions/git-convention.md`의 작업 흐름을 따른다.

1. **연관 이슈부터 확인한다.** 브랜치명의 `#번호`로 `gh issue view`를 실행해 실재하는 이슈인지 본다.
   - **이슈가 없으면 여기서 멈춘다.** PR을 만들지 말고 `/start-task`로 이슈부터 만들라고 알린다.
   - 이미 브랜치를 판 뒤에 발견했다면, 이슈를 만들고 그 번호를 PR 본문의 `Closes #N`에 넣는다. 브랜치명이 어긋난 것은 PR 본문에 밝힌다.
   - `#0` 같은 임의 번호를 쓰지 않는다.
2. **검증** — `/verify` 순서(typecheck→format:check→lint→test→build)가 통과했는지 확인한다. 안 돌렸으면 먼저 돌리고, **실패하면 PR을 만들지 않는다.** CI가 같은 검사를 다시 하므로 여기서 걸러야 왕복이 줄어든다.
3. **연관 이슈 업데이트** — 진행/완료 내용을 `gh issue comment`로 남긴다.
4. **`CHANGELOG.md` 기록** — `/changelog`의 절차대로 브랜치 커밋을 읽어 직접 작성한다. 사람에게 문장을 요청하지 않는다. 기록할 가치가 없으면 PR 본문에 사유를 적는다.
5. **README.md 정확성 확인** — 이번 작업으로 README의 서술이 사실과 달라졌는지 본다(스크립트 표·기술 스택 표·폴더 구조·기능 소개·실행 방법). 달라졌으면 갱신한다. **README는 프로젝트 소개 문서이므로 작업 목록을 적지 않는다.** 해당 없으면 건드리지 않는다.
6. 위 두 단계의 변경분을 이 브랜치에 커밋한다.
7. 브랜치를 push한다 — `git push -u origin <branch>`.
8. **PR 생성** — `gh pr create --base dev`로, 본문은 `.github/PULL_REQUEST_TEMPLATE.md` 형식(요약 / `Closes #N` / 변경 유형 / 백엔드 의존 / 체크리스트)을 채운다. **라벨은 직접 달지 않는다** — `.github/workflows/pr-label.yml`이 제목의 유형을 읽어 자동 부착하고, 제목을 고치면 따라 바뀐다. 이 라벨이 릴리스 노트의 그룹이 된다.
9. **CI와 리뷰 완료를 감시한다.** 아래를 백그라운드로 돌린다.

   ```bash
   gh pr checks <번호> --watch --interval 20
   ```

   **CodeRabbit도 상태 체크로 잡히므로 리뷰가 올라온 시점을 여기서 안다.** 감시가 끝나면 결과에 따라 갈라진다.

   | 결과 | 할 일 |
   | --- | --- |
   | 필수 체크 전부 통과 **그리고** CodeRabbit이 `Review completed` | `/review-reply` 절차(`.claude/commands/review-reply.md`)를 그대로 실행한다. **사람이 다시 시킬 때까지 기다리지 않는다** |
   | 필수 체크 실패 | 리뷰 처리보다 실패 원인을 먼저 고친다. 고쳐서 push했으면 **감시를 다시 건다** |
   | CodeRabbit이 `Review rate limited` | 리뷰가 돌지 않은 것이다. **통과로 읽지 말고** 사람에게 알린 뒤 판단을 받는다 |

   즉 `/review-reply`는 **통과와 리뷰 완료가 모두 확인된 경우에만** 실행한다. 리뷰 대응으로 push해서 CI가 다시 돌면 그때도 감시를 다시 걸고 같은 게이트를 적용한다.

   세션이 끊겨 감시가 중단돼도 누락되지는 않는다. 다음 세션에서 `session-start.sh`가, push 시점에 `record-check.sh`가 미응답 리뷰를 잡는다.

10. PR 링크와 리뷰 처리 결과를 함께 보고한다.

## 리뷰가 달린 뒤

리뷰 코멘트를 받으면 **모든 지적에 답한다.** 자세한 기준은 `docs/conventions/git-convention.md`의 "리뷰 응답"을 따른다.

- 지적을 **현재 코드에 먼저 대조한다.** CodeRabbit은 리뷰 시작 시점의 코드를 보므로 이미 고친 것을 지적하기도 한다.
- 유효하면 고치고, 무엇을 어떻게 고쳤는지 답한다. 유효하지 않으면 근거를 적어 닫는다.
- 답은 해당 스레드에 남긴다. PR 최하단 새 코멘트로 쓰지 않는다.

```bash
gh api repos/{owner}/{repo}/pulls/{번호}/comments/{코멘트ID}/replies -f body="..."
```

push와 PR 생성은 외부에 나가는 작업이므로 **사용자 승인 후 진행한다.**

**전제 확인** — 원격 저장소가 연결되어 있어야 한다. 없으면 멈추고 사용자에게 알린다.
