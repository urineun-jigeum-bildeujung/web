Figma 프레임을 코드로 구현하는 전체 흐름을 진행한다. `$ARGUMENTS`에서 대상과 범위 설명(선택)을 얻는다. 대상은 두 형태를 받는다.

- **Figma 프레임 URL** — 그대로 사용한다.
- **백로그 번호** (`1`, `3번` 등) — `.claude/figma-watch-snapshot.json`에서 `backlog` 필드가 그 번호인 프레임을 찾아 노드 ID로 URL을 만든다(콜론은 하이픈으로). 스냅샷이 없거나 번호가 없으면 멈추고 `/figma-watch` 첫 실행으로 백로그를 만들라고 안내한다.

둘 다 없으면 멈추고 요청한다.

1. **디자인 읽기** — `figma-design-to-code` 스킬을 먼저 로드한 뒤 `get_design_context`로 대상 프레임을 분석한다(필요 시 `get_screenshot` 병용). 스킬 로드는 Figma MCP의 선행 필수 조건이다.
2. **배치 계획 수립 → 사용자 확인 (게이트)** — 분석 결과로 다음을 정리해 사용자에게 보여주고 **승인받기 전에는 이슈·브랜치·코드를 만들지 않는다.**
   - 새 페이지인가 기존 화면 수정인가. FSD 어느 레이어·슬라이스에 두는가.
   - 서버/클라이언트 컴포넌트 경계 (AGENTS.md 5.2 기본 방침 기준).
   - 재사용할 기존 `shared/ui` 컴포넌트와 새로 만들 것.
   - 디자인에서 읽히지 않는 모호한 부분 — 인터랙션, 상태, 데이터 출처. 가정하지 말고 명시한다.
3. **이슈·브랜치 생성** — 승인되면 `/start-task` 절차대로 이슈를 만들고 브랜치를 판다.
4. **작업 산출물** — 규칙 2.8대로 `checklist.md`·`context-notes.md`를 만들고 시작한다.
5. **구현** — 아래 규칙을 지킨다. 세부는 각 컨벤션 문서를 따른다.
   - **색·간격은 `globals.css`의 기존 시맨틱 토큰에 매핑한다.** 매핑이 안 되는 디자인 값은 하드코딩하지 말고 멈춰서 보고한다. 디자인 토큰이 미확정(Pending)이라 임의 값은 나중에 전부 걷어내야 한다.
   - 모바일 우선, 4px 스케일 표준 단위 (`w-[100px]` 대신 `w-25`).
   - 이미지는 `next/image` + width·height(또는 fill), 아이콘은 react-icons.
   - 접근성 — 시맨틱 마크업, 라벨, 최소 탭 44×44.
   - 새 슬라이스면 `/new-slice` 뼈대와 폴더 README 규칙을 따른다.
6. **검증·커밋** — `/verify` 순서로 돌리고, 통과하면 논리 단위로 커밋한 뒤 산출물 파일을 삭제한다. **push와 PR은 하지 않는다** — 사용자가 `/pr`로 트리거한다.

**출처 표기** — 이슈 본문과 PR 본문에 원본 프레임 URL을 남겨 디자인과 구현을 추적할 수 있게 한다.
