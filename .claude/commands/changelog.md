---
description: 브랜치 커밋을 읽어 CHANGELOG의 [Unreleased]에 기록
---

현재 브랜치의 커밋을 읽어 `CHANGELOG.md`의 `[Unreleased]`에 항목을 추가한다. **사람에게 묻지 말고 직접 작성한다.**

## 1. 커밋 수집

기준 브랜치와의 차이를 읽는다. 기준은 보통 `dev`이고, 현재 브랜치가 `dev`면 릴리스 대상인 `main`이다.

커밋 메시지만으로는 사용자에게 보이는 변화인지 판단하기 어려우므로 변경 파일도 함께 본다.

```bash
git fetch origin --quiet

BASE=origin/dev
[ "$(git branch --show-current)" = "dev" ] && BASE=origin/main

git log --format="%s%n%b%n---" "$BASE..HEAD"
git diff --stat "$BASE..HEAD"
```

## 2. 문장으로 바꾸기

**커밋 메시지를 복사하지 않는다.** 커밋은 "무엇을 했나"를 개발자에게 설명하고, CHANGELOG는 "무엇이 달라졌나"를 읽는 사람에게 설명한다.

- 여러 커밋이 하나의 변화면 **한 줄로 합친다.** 커밋 수만큼 줄을 만들지 않는다.
- 작업 중 넣었다 뺀 것은 최종 상태만 남긴다. 과정은 기록하지 않는다.
- 수정 커밋(`fix`)이 이번 브랜치에서 만든 버그를 고친 것이면 별도 항목으로 쓰지 않는다.

| 커밋 | CHANGELOG |
| --- | --- |
| `feat(#12): 구독 상세 화면 추가`<br>`fix(#12): 구독 상세 로딩 상태 누락` | 구독 상세 화면 (#12) |
| `chore: eslint-plugin-boundaries 설치`<br>`chore: FSD 경계 규칙 설정` | FSD 레이어 경계를 ESLint로 강제 |

## 3. 분류 고르기

`추가` · `변경` · `수정` · `제거` · `개발 환경` 중에서 고른다. 커밋 유형을 참고하되 **사용자에게 보이는지를 우선한다.**

| 커밋 유형 | 기본 분류 |
| --- | --- |
| `feat` | 추가 |
| `fix` | 수정 |
| `design`·`style` | 사용자에게 보이면 변경, 아니면 개발 환경 |
| `refactor`·`chore`·`docs`·`test` | 개발 환경 |

기존 동작이 달라졌으면 유형과 무관하게 `변경`이다.

## 4. 기록

- 문장 끝에 `(#이슈번호)`를 붙인다. 브랜치명이나 커밋 메시지에서 찾고, 없으면 생략한다.
- `[Unreleased]` 아래 해당 분류에 추가한다. 분류가 없으면 만든다.
- 분류 순서는 `추가` → `변경` → `수정` → `제거` → `개발 환경`.
- 이미 같은 내용이 있으면 중복해서 넣지 말고 기존 줄을 다듬는다.

기록할 가치가 없다고 판단되면(오타 수정, 주석 정리 등) **쓰지 말고 그 사유를 한 줄로 보고한다.**

작성 규칙 상세는 `docs/conventions/git-convention.md`의 "변경 이력 기록"을 따른다.
