description: Figma 파일의 프레임 변경 감지 — 스냅샷 비교 후 프레임 단위 보고
argument-hint: [Figma 파일 URL — 첫 실행 때만 필수]
---

Figma 파일에 새로 올라오거나 바뀐 프레임을 감지해 보고한다. **새 프레임을 감지하면 `/from-figma`의 분석·배치 계획 단계까지 자동으로 진행해 승인 게이트에서 대기한다.** 코드·이슈·브랜치 생성은 게이트 승인 후에만 일어난다.

스냅샷 파일은 `.claude/figma-watch-snapshot.json`이다. git에 올라가지 않는 로컬 상태 파일이다.

1. **대상 파일 결정** — `$ARGUMENTS`의 Figma URL에서 파일 키를 얻는다. URL이 없으면 스냅샷 파일의 `fileKey`를 쓴다. 둘 다 없으면 멈추고 URL을 요청한다. URL의 파일 키가 스냅샷의 `fileKey`와 **다르면 감시 대상을 갈아타는 것이다** — 기존 스냅샷과 비교하지 말고(전부 삭제로 오탐된다) 첫 실행으로 취급해 새 기준선을 잡고, 대상 파일이 바뀌었음을 보고한다.
2. **현재 상태 읽기** — Figma MCP `get_metadata`를 nodeId 없이 호출해 페이지 목록을 얻고, 페이지마다 다시 호출해 트리를 읽는다. 도구가 로드되지 않았으면 ToolSearch로 먼저 로드한다. 인증 오류·읽기 실패 시 **스냅샷을 건드리지 말고** 멈춰서 사용자에게 알린다.
3. **지문 생성** — 페이지별 최상위 노드(frame·symbol)마다 `{노드 ID, 이름, 페이지, 크기, 직계 자식 수, 하위 트리 해시}`를 기록한다. 페이지 트리는 보통 100KB를 넘어 응답이 파일로 저장되므로 전체를 읽지 말고 `jq -r '.[].text'`로 XML만 꺼내 awk로 처리한다. 추출은 두 갈래로 **분리**한다 — **표시용 지문**(이름·크기·직계 자식 수)은 들여쓰기 2칸(최상위)·4칸(직계 자식) 줄만 세고, **하위 트리 해시**는 이와 별도로 프레임의 여는 태그부터 대응하는 닫는 태그까지 **모든 깊이를 포함한 전체 블록**을 추출해 `x=`·`y=` 속성을 제거한 뒤 `shasum`으로 계산한다. 2칸·4칸 줄만 해시하면 더 깊은 요소의 변경을 놓친다. 좌표를 빼는 이유는 캔버스 정리(프레임 이동)를 오탐하지 않기 위해서다. **페이지 목록이나 추출된 프레임 목록이 비어 있으면 파싱 실패로 간주한다** — 빈 결과를 전체 삭제로 해석하지 말고, 스냅샷을 건드리지 않은 채 중단해 보고한다.
4. **비교** — 스냅샷이 없거나 파일을 갈아탄 경우는 **첫 실행(새 기준선)**이다. 지금 상태를 저장하고, 개수 요약이 아니라 **현황판**을 보고한다.
   - 기준선에 담긴 최상위 프레임 **전체 목록**을 이름·링크와 함께 보여준다.
   - 각 프레임을 6단계와 같은 방식으로 구현 대조해 **구현 이력 있음(#N 표기) / 미구현 백로그**로 나누고, 미구현 항목에는 "`/from-figma <URL>`로 착수"를 안내한다.
   - 백로그는 확정이 아니라 **판단 참고용**임을 명시한다 — 스타일 가이드성 프레임(구현 대상 아님)과 이 워크플로 밖에서 수동 구현된 화면은 사람이 걸러야 한다.
   - 첫 실행에는 자동 착수를 적용하지 않는다 — 기존 프레임 전체를 한꺼번에 분석하는 폭주를 막기 위함이다.
   스냅샷이 있으면 노드 ID 기준으로 비교한다.
   - 새 ID → **새 프레임**
   - 사라진 ID → **삭제**
   - 같은 ID의 지문 변화 → **변경** (이름·크기·자식 수·페이지 중 무엇이 달라졌는지 `이전 → 현재`로 명시)
   - 같은 ID에서 다른 값은 그대로인데 해시만 다름 → **내부 구조 변경** (프레임 안쪽 요소의 추가·삭제·크기 변경)
   - 스냅샷 항목에 해시가 없으면(구버전 형식) 해시 검사는 건너뛰고, 이번 갱신 때 채운다
5. **보고** — 변경이 없으면 "변경 없음" 한 줄로 끝낸다. 있으면 프레임 이름과 링크(`https://www.figma.com/design/<파일키>/?node-id=<노드ID>`)를 목록으로 보여준다. **링크의 노드 ID는 메타데이터의 콜론을 하이픈으로 바꾼다** (`3304:805` → `node-id=3304-805`). 브라우저 URL은 하이픈 형식만 프레임을 연다. 터미널에서는 마크다운 링크가 클릭되지 않을 수 있으므로 원시 URL도 코드 블록으로 함께 표기한다.
6. **구현 여부 대조** — 감지된 각 프레임(새 프레임·변경·내부 구조 변경·삭제 모두)의 **하이픈형 노드 ID**로 이슈·PR 본문을 검색한다. `/from-figma`가 남기는 원본 프레임 URL이 검색 키다.
   - `gh issue list --state all --search "<하이픈형 노드 ID> in:body"` 와 `gh pr list --state all --search "<하이픈형 노드 ID> in:body"`
   - **변경·내부 구조 변경·삭제**가 구현 이력 있는 프레임에서 나면 → 보고에 "#N에서 구현된 화면이다 — 디자인이 바뀌었으니 코드 갱신이 필요할 수 있다"를 덧붙인다.
   - gh 미설치·미인증·오프라인이면 대조만 조용히 건너뛴다. 감지 보고를 막지 않는다.
7. **자동 착수 (새 프레임만)** — 보고 후 새 프레임에 대해 `/from-figma`의 1~2단계(디자인 분석 → 배치 계획)를 곧바로 실행하고 **게이트에서 사용자 승인을 기다린다.** 단, 6단계에서 **구현 이력이 확인된 새 프레임은 분석을 생략하고 기존 이슈를 안내한다** — 새로 만들 게 아니라 갱신 대상이고, 중복 구현을 막기 위함이다. 삭제·이름 변경·내부 구조 변경은 보고만 한다 — 다듬는 중인 프레임마다 분석을 반복하지 않기 위함이다. 새 프레임이 여러 개면 전부 분석하지 말고 목록을 보여준 뒤 어느 것부터 착수할지 묻는다.
8. **스냅샷 갱신** — 위 검증과 비교까지 전부 성공한 경우에만 지금 상태와 `fileKey`, 확인 시각을 저장한다. 갱신은 셸 명령이 아니라 Write 도구로 한다. **승인 거절은 감지가 완료된 것**이므로 그대로 갱신하지만, **자동 착수의 분석이 실패한(호출 한도·읽기 오류) 새 프레임은 스냅샷에서 제외해** 다음 회차에 다시 새 프레임으로 감지되게 한다. 여러 새 프레임 중 착수 대상 질문에 답이 없어 분석하지 못한 프레임은 이미 보고된 것이므로 갱신에 포함한다.

**감지 한계** — 내부 요소의 추가·삭제·크기 변경은 하위 트리 해시로 잡히지만, 색상·문구 수정과 요소의 순수 이동(좌표만 변경)은 메타데이터 지문에 드러나지 않는다. 이 커맨드의 목적은 "새 화면이 올라왔는지 알기"다. 미세 수정까지 봐야 하면 해당 프레임을 `get_screenshot`으로 직접 확인한다.

**루프 사용** — `/loop 30m /figma-watch`로 감싸면 주기적 알림이 된다. 루프 중에는 변경 없음이 반복되어도 소음을 내지 않는다.
