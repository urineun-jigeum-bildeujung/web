description: Figma 파일의 프레임 변경 감지 — 스냅샷 비교 후 프레임 단위 보고

---

Figma 파일에 새로 올라오거나 바뀐 프레임을 감지해 보고한다. 감지·보고까지만 하고 **구현은 시작하지 않는다.** 구현은 사용자가 결정하면 `/start-task`부터 기존 워크플로를 탄다.

스냅샷 파일은 `.claude/figma-watch-snapshot.json`이다. git에 올라가지 않는 로컬 상태 파일이다.

1. **대상 파일 결정** — `$ARGUMENTS`의 Figma URL에서 파일 키를 얻는다. URL이 없으면 스냅샷 파일의 `fileKey`를 쓴다. 둘 다 없으면 멈추고 URL을 요청한다.
2. **현재 상태 읽기** — Figma MCP `get_metadata`를 nodeId 없이 호출해 페이지 목록을 얻고, 페이지마다 다시 호출해 트리를 읽는다. 도구가 로드되지 않았으면 ToolSearch로 먼저 로드한다. 인증 오류·읽기 실패 시 **스냅샷을 건드리지 말고** 멈춰서 사용자에게 알린다.
3. **지문 생성** — 페이지별 최상위 노드(frame·symbol)마다 `{노드 ID, 이름, 페이지, 크기, 직계 자식 수}`를 기록한다. 페이지 트리는 보통 100KB를 넘어 응답이 파일로 저장되므로, 전체를 읽지 말고 `jq -r '.[].text'`로 XML을 꺼내 들여쓰기 2칸(최상위)·4칸(직계 자식) 줄만 awk로 추출한다.
4. **비교** — 스냅샷이 없으면 첫 실행이다. 지금 상태를 저장하고 "스냅샷 생성, 프레임 N개 기준선 설정"만 보고한다. 스냅샷이 있으면 노드 ID 기준으로 비교한다.
   - 새 ID → **새 프레임**
   - 사라진 ID → **삭제**
   - 같은 ID의 지문 변화 → **변경** (이름·크기·자식 수 중 무엇이 달라졌는지 명시)
5. **보고** — 변경이 없으면 "변경 없음" 한 줄로 끝낸다. 있으면 프레임 이름과 링크(`https://www.figma.com/design/<파일키>/?node-id=<노드ID>`)를 목록으로 보여주고, 새 프레임에는 "구현하려면 `/start-task`로 시작"을 덧붙인다. 터미널에서는 마크다운 링크가 클릭되지 않을 수 있으므로 원시 URL도 코드 블록으로 함께 표기한다.
6. **스냅샷 갱신** — 비교까지 성공한 경우에만 지금 상태와 `fileKey`, 확인 시각을 저장한다.

**감지 한계** — 프레임 내부의 색상·문구 수준 미세 수정은 지문에 드러나지 않을 수 있다. 이 커맨드의 목적은 "새 화면이 올라왔는지 알기"다. 미세 수정까지 봐야 하면 해당 프레임을 `get_screenshot`으로 직접 확인한다.

**루프 사용** — `/loop 30m /figma-watch`로 감싸면 주기적 알림이 된다. 루프 중에는 변경 없음이 반복되어도 소음을 내지 않는다.
