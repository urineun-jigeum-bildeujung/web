# 라우팅 설계

PRD v0.3, IA v0.6, UCS v0.1과 현재 App Router 구현을 대조해 정리한 라우팅 기준이다. 과거 초안이나 작업 과정은 포함하지 않으며, 실제 코드는 이 문서의 확정 항목을 따른다. 확정 기준은 IA v0.6이며, 작성 중인 IA v0.7 초안은 변경 가능성을 확인하는 참고 자료로만 사용했다.

## 기본 원칙

- `src/app/**/page.tsx`는 대응하는 `views` 공개 API만 렌더하는 얇은 라우트 파일로 유지한다.
- 동일 상품 상세는 진입 경로와 무관하게 `/products/[productId]` 하나를 사용한다.
- 상품·주문·리뷰처럼 식별 가능한 리소스는 의미가 드러나는 동적 세그먼트명을 사용한다.
- 검색어·필터·정렬·탭·페이지처럼 새로고침과 뒤로가기에서 유지할 상태는 URL 쿼리로 관리한다.
- 모달·바텀시트·일시적인 선택 상태는 별도 라우트로 만들지 않는다.
- 상품 목록과 상품 상세는 서버 컴포넌트를 우선한다.
- 인증과 API 계약이 필요한 동작은 계약 확정 전 추측해 구현하지 않는다.

## URL 쿼리 계약

현재 코드에서 확정된 쿼리는 다음과 같다.

| 화면 | 쿼리 | 허용값·의미 |
| --- | --- | --- |
| 온보딩 | `step` | `basic`, `detail`, `breed`, `health`, `done` |
| 나의 상품 후기 | `tab` | `writable`, `written` |
| 반려동물 프로필 | `tab` | `profile`, `products` |
| 상품 비교 | `slot` | 비교할 자리 인덱스 |
| 상품 비교 | `product` | 고른 상품 ID |
| 클레임 접수 | `type` | `cancel`, `return`, `exchange` |
| 리뷰 작성 | `orderItemId` | 리뷰를 작성할 구매 항목의 임시 식별자 |

검색·추천·리뷰 필터·타임딜 상태·주문 상태 쿼리는 백엔드 API와 PM·PD 정책 확정 후 이 표에 추가한다.

## 라우트가 아닌 상태

- 배송지 변경과 리뷰 필터 바텀시트.
- 반려동물 등록 완료 모달.
- 메인의 구매 후 반려동물 상태 체크.
- 일시적인 확인창과 드로어 열림 상태.
- 온보딩과 폼의 제출 전 입력값.

## 확인이 필요한 결정

| 항목 | 현재 판단 | 확인 대상 |
| --- | --- | --- |
| 최초 서비스 소개와 프로필 등록 온보딩 | `/onboarding`은 현재 프로필 등록에 사용 | PM·PD |
| 상품 상세 진입 경로별 분리 | `/products/[productId]` 하나로 재사용 | PM·PD |
| 추천 화면 유형과 기준 프로필 | `/recommendations` 유지, `petId` 전달 방식 미정 | PM·PD·백엔드 |
| 카드 등록 방식 | 토스 결제위젯 대체 여부 미정 | PM·PD |
| 결제 완료 주문 식별·PG 복귀 경로 | 실제 결제 승인은 아직 붙지 않았다. 대행사 계약과 사업자등록이 정해진 뒤 `/payment/done`에 승인·주문 식별을 붙인다 | 백엔드·결제 담당 |
| 장바구니·결제 화면 간 데이터 전달 | `/cart`에서 고른 상품과 `/payment/address`에서 고른 배송지가 다음 화면에 반영되지 않는다. 라우터 구조(쿼리 vs 상태)가 정해진 뒤 붙인다 | PD·백엔드 |
| 약관·개인정보 공개 경로 | 현재 마이페이지 하위지만 회원가입 접근을 위해 이동 검토 | PM·보안 |
| 주문별 외부 문의 | 외부 페이지에 `orderId` 전달 가능 여부 미정 | PM·연동 담당 |
| 관리자 타임딜 | 사용자 앱 저장소 범위 밖으로 제외 | 저장소 담당 |
| 반려동물 식별자 전달 방식 | 현재 `/mypage/pets`·`/mypage/pets/basic`·`/mypage/pets/body`·`/mypage/pets/health`에는 `petId`가 없다. 여러 아이 중 어느 아이를 다루는지는 화면 내 상태(PetSwitcher)로 정한다. API 계약과 상태 관리 방식이 확정된 뒤 동적 세그먼트 또는 쿼리 사용 여부를 결정한다 | PM·PD·백엔드 |

인증 미들웨어, API 호출, 결제 콜백, 동적 리소스의 `notFound()` 처리는 관련 계약이 확정된 뒤 구현한다.
