# 컴포넌트 컨벤션

컴포넌트를 **어디에 두고 어떻게 만드는지**를 다룬다. 네이밍은 [code-convention](code-convention.md), 레이어 구조는 [srp-convention](srp-convention.md), 스타일 토큰은 [design-convention](design-convention.md)이 상세다.

## 어디에 두는가

| 성격 | 위치 | 예 |
|---|---|---|
| 비즈니스 의미가 없다 | `shared/ui` | `PageHeader`, `EmptyState`, `Price` |
| 특정 도메인을 안다 | `entities/<도메인>/ui` | `MatchScoreBadge`, `ReviewCard` |
| 사용자 시나리오를 수행한다 | `features/<시나리오>/ui` | `ThemeToggle` |
| 한 화면에서만 쓴다 | 그 화면의 `ui` 폴더 | 온보딩 완료 일러스트 |

**판단 기준은 "이 컴포넌트가 도메인 타입을 알아야 하는가"다.** `Price`는 숫자만 받으므로 `shared`고, `MatchScoreBadge`는 적합도 점수라는 우리 서비스 개념을 담으므로 `entities/product`다.

`shared`에 도메인 타입이 들어오면 의존 방향이 뒤집힌다. ESLint(`boundaries/dependencies`)가 막지만, 타입을 `shared`로 옮겨 우회하지 않는다.

## 공용으로 올리는 기준

셋을 모두 만족할 때만 올린다.

1. **두 곳 이상에서 되풀이된다.** 한 곳뿐이면 그 화면 폴더에 둔다
2. **표시 항목이 화면마다 갈리지 않는다.** 갈리면 조각으로 나눠 화면이 조립한다
3. **비즈니스 의미가 없다.** 있으면 `entities`다

상품 카드가 2번에 걸린다. 같은 상품이라도 화면마다 보여주는 항목이 다르므로 하나로 묶으면 boolean prop이 열 개 넘게 붙는다. `ProductThumbnail`·`Price`·`MatchScoreBadge` 같은 조각만 공용으로 두고 카드는 화면마다 조립한다.

## 파일 헤더 주석

모든 컴포넌트 파일 첫 줄에 역할을 한 줄로 적는다. `src/shared/ui/`의 shadcn 생성 파일은 예외다(CLI가 덮어쓴다).

**PD팀 Figma는 와이어프레임에서 UI 시안으로 화면 단위로 바뀌는 중이다.** 시안을 근거로 만든 컴포넌트는 어느 단계(와이어프레임 / UI 시안)의 어느 화면 ID를 따랐는지 함께 남긴다. 화면을 UI 시안으로 옮길 때 무엇을 다시 봐야 하는지 파일에서 바로 보인다.

```tsx
// 화면 하단에 고정되는 버튼 줄. 1~2개 버튼과 비활성 상태를 다룬다.
// UI 시안 기준(onbo_001~005의 wrapper_button)이다.
```

아직 UI 시안이 없는 화면이면 와이어프레임 기준임을 적는다.

```tsx
// 후기 사진만 모아 보는 격자.
// 와이어프레임 기준(mypa_041)이라 디자인 확정 시 바뀔 수 있다.
```

근거 화면이 없고 IA 단위기능만 보고 만들었다면 그렇게 적는다.

```tsx
// 목록이 비었을 때 안내와 다음 행동을 보여준다.
// IA 기준(타임딜·배송지·검색 결과)이며 시안은 아직 없다.
```

## Props

| 규칙 | 내용 |
|---|---|
| 필수 prop을 최소화한다 | 대부분의 화면이 그냥 쓸 수 있어야 한다 |
| boolean을 늘어놓지 않는다 | `isPrimary` `isDanger` 대신 `variant="primary" \| "danger"` |
| 슬롯은 `ReactNode`로 받는다 | `left`·`right`처럼 자리를 열어 두면 화면이 채운다 |
| `className`을 받아 `cn`으로 병합한다 | 바깥에서 여백을 조정할 수 있어야 한다 |
| 나머지 HTML 속성은 넘긴다 | `...props`로 `aria-*`와 이벤트가 통과하게 한다 |

`cva`(class-variance-authority)로 variant를 정의한다. 이미 설치돼 있고 shadcn이 쓰는 방식이다.

## 스타일

[design-convention](design-convention.md)을 따르되 컴포넌트에서 특히 지킬 것이다.

- **색은 시맨틱 토큰만 쓴다.** `bg-primary`, `text-muted-foreground`. HEX를 적지 않는다
- **4px 스케일은 표준 단위로 쓴다.** `w-[100px]`이 아니라 `w-25`. ESLint가 잡는다
- **모바일 기준으로 쓰고** `md`·`lg`에서 확장한다
- 디자인 토큰이 아직 shadcn 기본값이므로, 지금 하드코딩한 값은 토큰 교체 때 전부 손봐야 한다

## 상태

와이어프레임에 상태가 그려져 있으면 전부 구현한다. 시안에서 확인된 상태들이다.

| 상태 | 확인된 곳 |
|---|---|
| 주 / 보조 / 비활성 | 온보딩·마이페이지 하단 버튼 |
| 선택 / 미선택 | 성별·중성화·체구 칩, 재입고 알림 카드 |
| 입력 전 / 입력 중 / 완료 | 텍스트 입력의 클리어 버튼 |

**비활성은 `disabled` 속성으로 준다.** 회색으로만 칠하고 클릭이 되면 접근성 검사에 걸리고 사용자도 속는다.

## 대기 상태

**서버를 기다리는 동안 화면이 가만히 있으면 안 된다.** 눌렸는지 알 수 없으면 사용자는 다시 누르거나 떠난다. 세 갈래로 가른다.

| 언제 | 무엇 | 왜 |
| --- | --- | --- |
| 화면을 **처음 그릴 때** | `Skeleton` | 아직 그릴 내용이 없다. 자리를 잡아 레이아웃이 밀리지 않게 한다 |
| **이미 그려진 UI**가 기다릴 때 | `LoadingSwap` | 그려진 것을 지우면 자리가 무너진다. 겹쳐서 바꾼다 |
| **낙관적 갱신**을 쓰는 자리 | **아무것도** | 이미 결과를 그려 놓았다. 대기 표시를 얹으면 오히려 끊겨 보인다 |

### `LoadingSwap`을 쓰는 법

버튼은 **라벨만** 바꾼다. 버튼째 갈아치우면 폭이 줄었다 늘어난다.

```tsx
<Button disabled={isSubmitting} onClick={onSubmit}>
  <LoadingSwap loading={isSubmitting}>작성 완료</LoadingSwap>
</Button>
```

아이콘 자리는 **아이콘째** 바꾸고, 아이콘이 16px보다 크면 스피너도 같이 키운다.

```tsx
<LoadingSwap loading={isSearching} label="다음 쪽을 불러오는 중" spinnerClassName="size-5">
  <Icon name="right" className="size-5" />
</LoadingSwap>
```

**문구는 하는 일에 맞춘다.** 기본값은 제출을 전제한 `"처리 중"`이고, 무언가를 받아 오는 자리는 `label`로 `"주문 내역을 불러오는 중"`처럼 바꾼다.

### `disabled`만 주고 끝내지 않는다

**눌리지 않는다는 것과 처리 중이라는 것은 다른 사실이다.** `disabled`는 앞만 말하므로, 사용자는 왜 안 눌리는지 모른 채 기다린다. 둘 다 필요하다 — `disabled`로 두 번 눌리는 것을 막고, `LoadingSwap`으로 왜인지 알린다.

### 어디를 봐야 하는가

`useMutation`을 쓰는 훅이 `isPending`(또는 `isSubmitting`)을 내주면 **그 값이 닿는 버튼에 대기 표시가 있어야 한다.** 훅에서 내주기만 하고 화면이 `disabled`에만 꽂아 두는 것이 가장 흔한 누락이다.

`.claude/hooks/pending-ui-check.sh`가 `.tsx`를 저장할 때 이것을 상기시킨다. 막지는 않는다 — 낙관적 갱신처럼 정당한 예외가 있다.

## 접근성

Lighthouse 접근성 95점이 목표다. `eslint-plugin-jsx-a11y` 규칙 31개가 저장 시점에 검사하지만 린트가 못 잡는 것들이 있다.

- **누르는 것은 `button`, 이동하는 것은 `a`/`Link`다.** `div`에 `onClick`을 달지 않는다
- 터치 대상 크기는 시안이 지정한 값을 따른다. 시안에 없으면 44×44가 기본이다 ([design-convention](./design-convention.md)의 "터치 UX")
- 색만으로 정보를 전달하지 않는다. 품절·할인·선택 여부는 텍스트나 아이콘을 함께 쓴다
- 토글 버튼은 `aria-pressed`, 열고 닫는 것은 `aria-expanded`를 준다
- 아이콘만 있는 버튼에는 `aria-label`을 준다

## 테스트

[code-convention](code-convention.md)의 테스트 절을 따른다. 컴포넌트는 파일 옆에 `<파일명>.test.tsx`를 둔다.

- **렌더링 스모크**를 기본으로 한다. 셀렉터는 `getByRole` 같은 역할 기반을 쓴다
- 계산이 들어간 것(할인율, 남은 시간)은 **케이스를 나눠 검증한다**
- 검증할 것이 없으면 만들지 않고 그 이유를 보고에 밝힌다. 껍데기 테스트는 통과율만 올린다

## 갤러리에 올린다

`shared/ui`나 `entities`의 `ui`에 공용 컴포넌트를 추가하면 `/dev` 갤러리에도 구역을 만든다. 이 화면이 "무엇이 이미 있는가"의 목록이기도 해서, 갱신하지 않으면 같은 것을 다시 만들게 된다 (#75).

- `src/views/dev-gallery/ui/dev-gallery-view.tsx`에 `Section` 하나를 더한다. 시안에 있는 상태(고른 것·비어 있는 것·오류)를 함께 늘어놓는다
- `dev-gallery-view.test.tsx`의 구역 목록에도 이름을 더한다
- 화면 하나를 통째로 차지하는 골격은 넣지 않는다. 중첩하면 머리말과 하단 버튼 줄이 두 개씩 생긴다. "여기서 볼 수 없는 것" 구역에 어느 화면에서 볼 수 있는지 적는다

## 만들지 않는 것

| 상황 | 대신 |
|---|---|
| shadcn이 제공한다 | CLI로 받는다. 의존 패키지도 CLI가 함께 설치하므로 손으로 설치하지 않는다 |
| 한 화면에서만 쓴다 | 그 화면 폴더에 둔다 |
| 표시 항목이 화면마다 갈린다 | 조각으로 나눈다 |
| 외부 위젯이 그린다 | 만들지 않는다. 결제수단 선택은 토스 결제위젯이 그린다 |

## 체크리스트

1. [ ] 위치가 맞는가 — 도메인 타입을 알면 `entities`, 모르면 `shared`
2. [ ] 파일 첫 줄에 역할 주석과 근거(와이어프레임 화면 ID 또는 IA)가 있는가
3. [ ] boolean prop을 늘어놓지 않고 `variant`로 묶었는가
4. [ ] `className`을 받아 `cn`으로 병합하는가
5. [ ] 색을 토큰으로만 썼는가
6. [ ] 시안에 있는 상태를 모두 구현했는가
7. [ ] 누르는 것이 `button`인가, 아이콘 버튼에 `aria-label`이 있는가
8. [ ] 테스트를 뒀는가, 없다면 이유가 있는가
9. [ ] `/dev` 갤러리에 구역을 만들고 그 테스트의 목록에도 더했는가
10. [ ] 서버를 기다리는 자리에 대기 표시가 있는가 — `Skeleton` / `LoadingSwap` / 낙관적 갱신이라 없음 중 하나
