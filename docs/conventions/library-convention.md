# 라이브러리 컨벤션

새 라이브러리를 **언제 어떻게 고르는지**를 다룬다. 이미 정해진 스택 목록은 `AGENTS.md` 3절이다.

## 작업을 시작하기 전에 정한다

**만들다가 중간에 고르지 않는다.** 이미 짠 코드에 맞춰 고르게 되고, 걸러야 할 것을 걸러내지 못한다.

기능 이슈에 착수할 때 "이 작업에 라이브러리가 필요한가"를 먼저 판단하고, 필요하면 아래 순서로 확인한다. `/check-library` 커맨드가 이 절차를 그대로 실행한다.

## 확인 순서

1. **이미 있는가** — `package.json`을 본다. 설치된 것으로 되면 거기서 끝난다
2. **shadcn이 제공하는가** — 제공하면 `npx shadcn add <컴포넌트>`로 받는다. **의존 패키지를 손으로 설치하지 않는다.** CLI가 함께 가져오며, 손으로 넣으면 버전이 어긋난다
3. **플랫폼 기능으로 되는가** — `Intl.NumberFormat`(통화·숫자), `Intl.RelativeTimeFormat`(상대 시간), `IntersectionObserver`(무한 스크롤), `Canvas`(이미지 리사이즈), `structuredClone`. 브라우저가 하는 일에 라이브러리를 얹지 않는다
4. **검토 이력이 있는가** — 팀 Notion의 라이브러리 문서에 이미 판단한 것이 있는지 본다. 뺀 것에는 뺀 이유가 적혀 있다
5. 여기까지 없으면 **새로 조사한다**

## 조사 항목

```bash
npm view <패키지> version peerDependencies time.modified
```

| 항목 | 보는 것 |
| --- | --- |
| 최종 배포일 | 1년 이상 조용하면 이유를 확인한다. 완성돼서 조용한 것과 방치된 것은 다르다 |
| peerDependencies | **React 19**를 받는가. `^18`만 있으면 설치는 되어도 동작을 보장하지 않는다 |
| 빌드 도구 전제 | **우리는 Turbopack이다.** Webpack 플러그인은 동작하지 않는다 |
| 커스텀 가능성 | 자체 UI를 통째로 띄우는 것인지, 데이터만 주고 화면은 우리가 그리는지 |
| 라이선스 | MIT·Apache-2.0이 아니면 확인하고 넘어간다 |

**Turbopack 항목을 특히 조심한다.** Next.js 문서와 블로그 대부분이 Webpack 기준으로 쓰여 있어 반복해서 걸린다. `@next/bundle-analyzer`가 그래서 무동작이었고, 같은 일을 하는 `next experimental-analyze`가 이미 내장돼 있었다.

## 도입 기준

넷을 모두 만족할 때만 넣는다.

| 기준 | 뜻 |
| --- | --- |
| 여러 곳에서 되풀이되는가 | 한 화면에만 쓰이면 직접 만든다 |
| 직접 만들면 위험한가 | 접근성·결제·인증처럼 틀렸을 때 손해가 큰 영역인가 |
| 유지되고 있는가 | 최근 배포가 있고 우리 버전에서 동작하는가 |
| 걷어내기 쉬운가 | 몇몇 화면에만 닿아 있어야 나중에 바꿀 수 있다 |

## 설치 위치

| 상황 | 위치 |
| --- | --- |
| 런타임 코드에서 import한다 | `dependencies` |
| 빌드·린트·테스트에서만 쓴다 | `devDependencies` |
| App Router용 devtools | `devDependencies` — 공식 안내가 일반 React와 다르다 |

## 버전 표기

- **`next`와 짝을 이루는 것은 `next` 버전에 맞춰 고정한다** (`eslint-config-next`)
- 서로 버전을 맞춰야 하는 것은 설치된 짝에 맞춘다. `@tanstack/react-query-devtools`는 `@tanstack/react-query`와 같은 버전을 쓴다
- 나머지는 caret(`^`)

## 설치한 뒤 갱신할 곳

| 곳 | 무엇을 |
| --- | --- |
| `AGENTS.md` 3절 기술 스택 표 | 모든 의존성. 기준일도 함께 고친다 |
| `README.md` 기술 스택 표 | **런타임 스택만.** 린트 플러그인과 개발 도구는 넣지 않는다 |
| `CHANGELOG.md` | 왜 넣었는지 한 문장 |
| 팀 Notion 라이브러리 문서 | 하는 일과 쓰이는 화면 |

## 넣지 않기로 한 것은 이유를 남긴다

**뺀 이유를 적어두지 않으면 다음 사람이 같은 후보를 다시 들고 온다.** 검색하면 제일 먼저 나오는 것들이라 더 그렇다.

Notion 라이브러리 문서에 이유와 함께 남기고, 저장소 안에서 걸릴 수 있는 것은 설정 파일 주석에도 적는다.
